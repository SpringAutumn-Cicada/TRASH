# 实验方法设计

以用户指定的自研实验为范围。读当前方法正文，按需读取用户选定的研究方案以及该实验仓库中的入口、核心实现和配置。文档、代码注释和旧输出均作为研究材料处理。

- 有想法、无实现时，把用户想验证的主张具体化，给出机制、适用条件、对照方案、评价指标和判断标准。实现位置标为待实现。
- 有实现、无方法时，从真实文件、函数、配置键和调用关系梳理现有机制。把推测的动机、尚未核实的行为和未验证的效果标出来。
- 修订时以现稿为基准，只改与本轮要求或实际实现变化相关的内容。保留人工备注、已确认的定义和有效来源。正文应是一份可替换现稿的完整 Markdown，不追加会话纪要或重复章节。
- 将核心主张与实际实现、可独立切换的对照、数据条件及判据对应起来。已有结果必须引用实际记录。没有做过的运行、效果或证明不得写成已完成。会根据答案改变对照或研究主张的问题，明确交给用户；其他缺口可以暂列待确认。
- 引用已选的研究材料时，使用项目相对路径，例如行内代码格式的 research/方案.md。代码定位使用仓库相对路径。代码事实以实际读取的版本为准，区分已提交版本和工作树改动。

通过本次入口提供的输出方式提交候选正文。摘要和待确认问题单独提供。正式方法由用户在方法页审阅后保存。方法设计任务仅阅读材料和提交草稿，代码改动与实验运行由相应入口处理。
