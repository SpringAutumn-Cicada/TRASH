# 面向 Agent 的研究记忆

Wiki 负责让后续 Agent 快速找到认识、证据、分歧和待解决问题。卡片给人阅读，详细实验表格和方法说明留在详细卡片，Wiki 通过链接引用，不重复写长篇论文解读。

## 主题边界

项目题目只作为关联背景，不是主题边界。顺序必须是：开放读取论文真实问题/机制/条件/异常/局限 → 跨文献比较、聚类和去重 → 判断项目关联。保留有独立知识价值但暂无项目关联的主题，不为迎合项目题目编造联系。研究方向和采用决策由用户决定。

## 单篇线索笔记（level: single）

只依据本篇完整图文阅读及双卡片，保留任务指定 source_id 和 wiki-<source_id> ID。正文建议300–600字：何时读取、重要机制或条件（链接到双卡片）、候选主题线索、与项目关联（允许暂无直接关联）、未知项。没有独立线索时明确写“暂未发现”，不凑主题、不凭常识扩写。单篇线索不是跨文献验证过的主题结论。

## 主题发现清单（level: discovery）

严格使用实际输入材料，从共同假设、分歧、异常实验、评价错配、适用边界等发现具体问题。合并同义主题；input.json 的 topic_index 若有已有主题索引，同一问题优先沿用已有标题和语义边界，避免同义换名重复创建。索引最多列100项，topic_index_total 大于已列数量时不能声称已核对全部历史主题。不按论文顺序逐篇复述，也不固定套“背景/方法/数据集”几个主题。优先质量，无合适主题时写“未发现可整理主题”作为空清单，最多8个正式主题/假设。

直接输出 Markdown，不返回正文 JSON。自动发现任务使用以下二级标题，标题前缀由平台读取；每项写清问题、依据、为何值得独立整理、证据ID与链接、项目关联。标记含义不能混淆：

- `## 知识主题：具体问题`：实质证据支持。通常来自多篇，单篇必须另写 `单篇价值：` 并给出完整机制/问题为何足以独立整理的理由。
- `## 候选线索：具体问题`：单篇提及或证据不足，留在清单，不自动创建正式主题。
- `## 研究假设：具体问题`：从材料推导但尚未验证，写清动机、验证方式和推翻条件，不标成事实。

每项证据使用真实材料ID，如 `card-source_...-key` 或输入的分组Wiki ID，并给相对链接。分组总结必须保留原始卡片ID及来源，不让分层摘要丢失出处。不得引用未提供或不存在的材料。

## 知识主题（level: topic）/研究假设（level: hypothesis）

主题正文软目标800–1500字，必要时拆子主题，不硬截断或省略关键条件。假设页在标题和结论处明确“待验证”。统一结构：

```markdown
---
knowledge_version: 2
id: wiki-由任务指定
kind: wiki-page
level: topic
---
# 具体研究问题

## 何时读取
适合回答的问题、关键词和不适用的范围。此段用于检索索引。

## 核心认识
结论；成立条件；证据链接。每项关键认识就近引用，精确数字回查详细卡片/原文。

## 证据与分歧
支持、反例、不同实验设置与不能直接比较的地方。

## 未知与待验证
材料缺口、假设、验证方式及推翻条件。

## 项目关联
直接相关/潜在相关/暂无直接关联。保留用户明确决策与理由，不替用户改变方向。

## 深入阅读
相关卡片、原文及其他主题的相对链接。
```

只综合实际读取的材料；仅有摘要标明范围，不把不同数据集/划分/粒度的结果直接排名。先关键卡片，再按需要详细卡片和PDF。更新优先修订受影响结论，保留人工决策、稳定ID和来源，不自动采纳。

## 项目总览（level: overview）

软目标500–1000字，作为导航而非整本知识库：研究目标、当前方向、关键认识、主题入口、候选线索与假设入口、待解决问题。包含暂无直接项目关联但有知识价值的主题，不把待验证假设写成既定结论。
