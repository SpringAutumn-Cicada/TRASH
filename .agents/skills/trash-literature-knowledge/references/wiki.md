# 面向 Agent 的研究记忆

Wiki 负责让后续 Agent 快速找到认识、证据、分歧和待解决问题。单篇方法与实验细节保存在对应职责页，原文出处统一保存在 evidence.md。

## 主题边界

项目题目只作为关联背景，不是主题边界。顺序必须是：开放读取论文真实问题/机制/条件/异常/局限 → 跨文献比较、聚类和去重 → 判断项目关联。保留有独立知识价值但暂无项目关联的主题，不为迎合项目题目编造联系。研究方向和采用决策由用户决定。

## 单篇 Wiki

单篇全文严格使用 references/paper-wiki.md 的职责页结构与统一依据，不生成额外单文件研究记忆。跨论文任务按需读取 whoami 导航、方法、结果和 evidence 页，保留材料范围。

## 分批总结（level: summary）

分批总结用于预算内逐层归纳，不自动成为正式主题。一级标题根据实际材料的机制或问题命名；内容杂时用两三个主要方向加“分批总结”，不以“文献知识第几层分组几”命名，不虚构材料具有统一主题。内部任务名只放“## 批次标识”，不修改ID或路径。
必须包括“## 何时读取”的一句内容概述、“## 覆盖方向”的具体问题，以及“## 材料范围”的实际来源ID、下层总结、缺失和压缩范围；其余正文保存有证据的认识、分歧、未知及候选线索。保留原始知识页ID和出处，不因多层压缩丢失证据；发现方向不等于证实结论。遵守任务字符预算，不额外调用模型来起名。

## 主题发现清单（level: discovery）

严格使用实际输入材料，从共同假设、分歧、异常实验、评价错配、适用边界等发现具体问题。合并同义主题；input.json 的 topic_index 若有已有主题索引，同一问题优先沿用已有标题和语义边界，避免同义换名重复创建。索引最多列100项，topic_index_total 大于已列数量时不能声称已核对全部历史主题。不按论文顺序逐篇复述，也不固定套“背景/方法/数据集”几个主题。优先质量，无合适主题时写“未发现可整理主题”作为空清单，最多8个正式主题/假设。

直接输出 Markdown，不返回正文 JSON。自动发现任务使用以下二级标题，标题前缀由平台读取；每项写清问题、依据、为何值得独立整理、证据ID与链接、项目关联。标记含义不能混淆：

- `## 知识主题：具体问题`：实质证据支持。通常来自多篇，单篇必须另写 `单篇价值：` 并给出完整机制/问题为何足以独立整理的理由。
- `## 候选线索：具体问题`：单篇提及或证据不足，留在清单，不自动创建正式主题。
- `## 研究假设：具体问题`：从材料推导但尚未验证，写清动机、验证方式和推翻条件，不标成事实。

每项证据使用真实材料ID，如 `wiki-source_...--results--results` 或输入的分组Wiki ID，并给相对链接。分组总结必须保留原始知识页ID及来源，不让分层摘要丢失出处。不得引用未提供或不存在的材料。

## 知识主题（level: topic）/研究假设（level: hypothesis）

主题正文软目标600–1200字，必要时拆子主题，不硬截断或省略关键条件。假设页在标题和结论处明确“待验证”。统一结构：

```markdown
---
knowledge_version: 2
id: wiki-由任务指定
kind: wiki-page
level: topic
---
# 具体研究问题

## 何时读取
适合回答的问题、关键词和不适用的范围。此段用于检索索引。

## 核心认识
结论；成立条件；证据链接。每项关键认识就近引用，精确数字回查结果页、依据页及原文。

## 证据与分歧
支持、反例、不同实验设置与不能直接比较的地方。

## 未知与待验证
材料缺口、假设、验证方式及推翻条件。

## 项目关联
直接相关/潜在相关/暂无直接关联。保留用户明确决策与理由，不替用户改变方向。

## 深入阅读
相关 Wiki、原文及其他主题的相对链接。
```

只综合实际读取的材料；仅有摘要标明范围，不把不同数据集/划分/粒度的结果直接排名。先读论文总览，再按需要读取方法、结果、依据页和 PDF。更新优先修订受影响结论，保留人工决策、稳定ID和来源，发布后直接可用，后续人工编辑调整；未经核实的事实和待验证假设仍须明确标记。

## 项目总览（level: overview）

软目标400–800字，作为导航而非整本知识库：研究目标、当前方向、关键认识、主题入口、候选线索与假设入口、待解决问题。包含暂无直接项目关联但有知识价值的主题，不把待验证假设写成既定结论。

## 增量维护与连接约定

新材料完成单篇分析后，整合直接受影响的主题，保持原有 ID 和文件路径。先查询导航、标题和别名，再读相关主题正文；同义或相同问题补充原页，避免换名另建。发现清单中命中已有页时在该项写 `已有主题ID：wiki-真实ID`，保留其题目与知识边界。索引未覆盖全库时说明范围。每轮最多8个正式主题，候选不足不凑数；复杂主题按独立问题拆分，正文默认600–1200字，总览400–800字，可为必要条件和证据合理超出。

正文推荐：何时读取、核心认识、分歧与边界、关联知识、引用依据、待验证问题。新增事实更新对应结论；存在冲突时并列证据和实验条件，不擅自消除分歧。更新既有总览时保留本轮未提供的旧主题入口，不能把局部覆盖写成全库总结。人工决策与补充保留；有新证据冲突时说明，不静默改写。

平台区分三类关系：
- 导航：`[主题](../topics/wiki-ID.md)`，用于进一步阅读，不据此推导结论。
- 知识关系：在“关联知识”中写 `- 对比：[主题](../topics/wiki-ID.md) — 粒度不同，不能直接比较指标。`；关系可用支持、限制、对比、分歧、扩展、验证、相关，每条解释为什么相关。
- 证据：在“引用依据”或“证据依据”栏目列来源，或任意栏目写 `- 依据：[实验结果](../papers/source_ID/results/results.md) — 支持哪条认识及适用条件。`。只有真正用作依据的页面写为证据；不能把所有相关页面都作为证据。

关键结论就近引用，并在引用依据中列出实际读取的知识文件。PDF 页码证据保留原链接。不得为了增加连通度编造关系或链接。平台自动维护反向链接、索引、来源 hash 和日志，无需在两页重复手工补链接，也不编辑 .trash 文件。需要别名时使用“## 别名”后一行以顿号分隔的名称，不更改稳定文件名。

## 问答沉淀与维护

问答先 navigation/search 获取轻量索引，必要时 context 获取预算内相关正文及一跳关联；按需 relations 和 get 深入。报告实际读取页、遗漏项和证据范围。短答或临时讨论不生成新页。用户要求整理、更新或记住研究知识时，有来源且可复用的认识优先补入已有页；只有独立问题才新建页，通过 publish 提交 Markdown 工作副本。没有写入授权时在回复中指出可沉淀内容，不擅自保存。

maintenance/health 只检查缺失链接、孤立页、同名页和待更新项，不证明观点正确。用户要求语义维护时，再定向读取证据识别重复主题、条件差异、冲突和知识空白；整理合并需保留被引用的旧入口或调整关联，不删除无法解释的历史。主题不局限于项目题目，不强制所有 Wiki 必须有关联。
