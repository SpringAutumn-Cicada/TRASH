# TRASH 实验代码同步

先确认当前对话绑定的仓库和用户要求的操作范围。用本轮工作目录的 `python3 project_tool.py` 调用平台工具，通过 stdin 传入 JSON。按需读取 [工具参数与结果](references/tools.md)。

- **只提交。** 核对本地基线和目标文件差异，调用 `git-commit` 直接提交，只列出本次应提交的仓库相对文件。记录返回的完整 SHA 和基线。工具返回已创建的 SHA 时，即使校验或后续同步失败，也先核对该提交，避免重复提交。
- **只同步或需要固定远端检出。** 用户已要求同步时，调用 `autodl-targets` 核对主机和项目工作区，Agent 确认绑定仓库和目标完整 SHA 后直接调用 `git-sync-upload`。若有多个可用主机且无法确定目标，先请用户指定。平台核验 bundle 和 Git 检出，返回检出目录、版本记录 ID 和校验信息。已登记的版本用 `git-sync-versions` 查询。完整 SHA 是本次同步的目标，不随本地 HEAD 变化。
- **按版本运行。** 读取用户指定的项目配置，核对主机、数据集和启动参数。调用 `git-sync-plan` 创建独立草稿。协调派单用 `coordination-draft` 登记新方案，或用 `coordination-plan` 登记已有版本。`expects_runs` 为真时，成员完成后平台自动排队，由 Runner 预检查、打包、上传并检出指定提交。为假时只保存方案。用 `git-sync-runs` 查看已发起的运行，报告实际状态、完整提交、配置哈希、运行编号和产物路径。标注缺失的预检或回执。
- **导回远端提交。** 从 `git-sync-versions` 获取已有的版本记录 ID，使用用户指定的远端完整 SHA 发起 `request-git-import-choice`。确认后平台核验部署基线和 bundle，将原始 SHA 导入独立审查分支。向用户报告分支、基线和差异摘要。

确认卡续接时区分平台已执行的动作和仍待执行的动作。只做用户要求的阶段。上传只传输文件。独立草稿可供后续发起运行。没有主机、提交或真实配置时说明缺失项，避免猜测。Git bundle 携带目标提交可达的历史，不配置 Git remote、推送、合并或覆盖旧检出。提示版本、预算和依赖版本随具体实验填入。
