# TRASH 文献主题综合

以具体研究问题或机制矛盾为主题，综合背景、方法、结果与可复用认识；不按论文顺序拼接摘要，不机械创建“背景”“方法”“实验”三个大主题。仅使用本次选定、已发布的有效 Wiki 与按需独立依据，不读取 PDF、历史任务或自动联网。未覆盖不等于领域空白，被引工作不算独立已读来源。

## 模式与边界

- `topic-discovery`：发现并去重多个主题，输出发现清单，不生成主题正文。充分支持者为知识主题；材料不足者为候选线索；推断为研究假设。一篇可支持多个主题，不固定数量。平台负责分批展开和状态目录。
- `topic` / `comparison`：围绕一个明确问题生成主题 Wiki 组；总览必需，方法比较、结果分歧、可复用认识按独立价值增加子页。简单主题仅总览即可。路径与稳定 ID 由任务提供。
- `summary`：仅为预算归纳材料，保留逐篇问题、机制、条件、差异、未知及原始引用，不把分组当正式主题。
- `overview`、关联维护及用户要求的问答沉淀遵守 references/wiki.md，不自动触发其他模式。

地图、大背景和方向探索使用各自独立技能，不强制串行调用。不得执行安装、模型外调用或完整实验设计。

## 阅读与综合

先用总览、研究问题和贡献定位；判断背景必须读相关背景，判断机制必须读方法，比较效果/代价必须读结果；精确数字、争议和强结论补读对应独立依据。索引及链接存在不等于已读。预算外材料在工作副本按需补读，不用中间总结替代原始出处。

每个关键认识说明支持论文、成立条件与反例，区分原文事实、跨论文归纳、待验证推断。任务、数据划分、监督条件、标签/检测粒度或指标不同，不直接排名；原文未解释时不编造因果。背景和可复用认识分点，方法解释机制差别而非组件清单，不写配置、命令、依赖或操作教程。

同一问题优先更新现有主题，按边界而非仅名称去重。保留人工补充、稳定入口及本轮未覆盖认识，说明受新材料影响的变化。材料不足如实记录，不靠删除有效内容或虚构依据通过校验。

输出协议、各模式结构及定向修复见 [references/synthesis.md](references/synthesis.md)；公共引用与维护约定见 [references/wiki.md](references/wiki.md)。本次调用内利用已读材料做必要自查，有具体疑点才补读片段，不固定整组回读，不增加审核任务、脚本或其他 Skill 调用。
