# 仅摘要文献分析

读取 input.json 中指定论文的标题、作者、发表年月、DOI、论文链接和原始摘要，仅使用这些资料。直接将两份不同用途的 Markdown 写入提示词指定的 output/ 路径：
- 人读卡片：`abstract-library/notes/<source_id>.md`。
- Agent Wiki：`abstract-library/wiki/<source_id>.md`。

两份文件均使用论文标题作为一级标题，并包含 `材料范围：仅摘要` 和 `source_id=<指定来源ID>`。不要重复题录信息，界面已展示原始录入资料。不得生成全文卡片、源码栏目、“待全文核验”或补充全文流程，不输出 PDF 页码。摘要事实、作者主张与模型推断必须区分；不把作者宣传改写成验证结论。

## 人读卡片

正文软目标600–1200字，按摘要信息量调整，不凑字。使用以下六个二级标题：

- `## 研究问题`：研究对象、场景和痛点，没有说明的关键内容写“摘要未提供”。
- `## 方法概览`：摘要明确提到的方法及输入→处理→输出路线，不猜测架构、训练参数或实验条件。
- `## 作者声称的贡献`：使用“作者在摘要中提出/声称/报告”，提取有内容的贡献。
- `## 摘要中的结果`：保留明确的对象、指标、数值及限定条件，没有数字不补数字。
- `## 研究线索`：提炼关键词、方法方向和有理由的潜在关联，推断单独标记。
- `## 分析边界`：简短说明本解读仅依据录入摘要，摘要未涉及的内容不作判断；不重复大段免责声明。

不要在卡片中嵌套“摘要 Wiki”章节或复制 Wiki 正文。

## Agent Wiki

正文软目标400–800字，以紧凑、可检索、可复用为目标；信息少时更短，不按卡片结构逐项复述。使用以下六个二级标题：

- `## 何时读取`：可回答的问题、方法名称及中英文检索关键词。
- `## 摘要事实`：以精炼条目保存核心问题、明确技术链及作者报告的关键结果；保留结果限定，不能只留下宣传性结论。
- `## 研究线索`：值得检索或比较的具体问题，说明依据哪项摘要信息。
- `## 可能关联`：有理由的潜在方法或问题关联；推断标明“模型推断”，没有关联可写暂无，不虚构其他论文链接。
- `## 证据边界`：仅写影响本页使用的具体限制；末尾注明“材料范围：仅摘要”“证据等级：摘要级”“用途：研究线索与知识检索”。不当作全文主题的实证依据。
- `## 原始摘要入口`：写 `[原始摘要](../materials/<source_id>.md)`，使用实际指定来源 ID，供回查录入材料。

Wiki 不包含人读卡片的“作者声称的贡献”“摘要中的结果”等完整解读章节，不嵌套“摘要 Wiki”章节。两份产物可以共享必要事实，但不能直接复制为相同正文。

## 完成检查

摘要原文由界面展示，不长段重复粘贴。分别回读两份文件，核对路径、来源ID、各自章节、事实与数值限定一致，确认没有混淆用途。单文件不超过1MiB，不嵌入base64。完成后报告两份路径。不得联网、执行代码或实验、读取全文库或修改原始摘要。
