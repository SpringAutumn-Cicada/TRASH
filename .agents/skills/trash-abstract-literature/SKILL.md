# 仅摘要文献分析

读取 input.json 中指定论文的标题、作者、发表年月、DOI、论文链接和原始摘要，仅使用这些资料。直接将两份 Markdown 写入提示词指定的 output/ 路径：摘要解读使用 `abstract-library/notes/<source_id>.md`，摘要 Wiki 使用 `abstract-library/wiki/<source_id>.md`。

输出两份 Markdown：第一份是给人看的摘要解读，第二份是给 Agent 检索的摘要 Wiki，不生成全文卡片，不生成源码信息，不生成“待全文核验”，不提出补充全文流程，也不输出 PDF 页码。必须包含一级标题、`材料范围：仅摘要`、`source_id`，并按以下六个二级标题组织：

## 研究问题
摘要明确讨论的研究对象、问题、场景和痛点。没有说明的内容写“摘要未提供”。

## 方法概览
只记录摘要明确提到的方法名称、技术路线、模型、数据或系统组件。不得猜测网络结构、训练流程、参数或实验条件。

## 作者声称的贡献
使用“作者在摘要中提出/声称/报告”，列出摘要中明确表达的贡献，不把宣传性表述改写成已验证事实。

## 摘要中的结果
只记录摘要出现的实验对象、指标、数值、对比结论或应用效果。没有具体数字就保留“摘要未提供具体数值”。

## 研究线索
提炼可用于后续检索和研究思考的关键词、方法方向、潜在关联与问题。明确标记为“摘要线索”或“模型推断”，不能写成正式主题证据。

## 摘要 Wiki
写成面向 Agent 的研究线索入口，包含何时读取、摘要事实、研究线索、可能关联和证据边界。末尾固定写材料范围：仅摘要、证据等级：摘要级、用途：研究线索与知识检索。不得混入全文主题证据。

## 分析边界
固定说明：本解读仅依据用户录入摘要；不代表对全文、实验细节、源码或可复现性的核验。摘要没有涉及的内容不作判断。

摘要原文由摘要库界面直接展示，分析结果避免长段重复粘贴。正常输出约600–1200字，不嵌入base64，单文件不超过1MiB。完成后回读目标文件并报告路径。不得联网、执行代码或实验、读取全文库或修改原始摘要。
