# Thesis Research Agent & Science Hub

> 项目简称：`trash`
>
> 项目阶段：Phase 1 本地项目与文献工作台
> 用户界面：简体中文
> 文档版本：0.4

## 1. 项目简介

`trash` 是一个本地优先、面向科研项目的开源工作台。它通过研究方向模块组织文献调研、研究方案、实验执行、结果分析和论文写作；通过可插拔 Agent 适配器调用用户选择的 Agent；通过本地 Git 工作区和 SSH Runner 支持本机研究与远程实验。

首个研究方向模块为 APT 检测与溯源。MVP 的可验收成果为研究方案、实验报告和论文初稿。平台不承诺无人参与地完成可信科研结论，研究者负责确认研究问题、方案、结论和最终稿件。

项目简称 `trash` 带有对低质量科研产出的讽刺意味。该表达针对科研产出质量问题，不针对使用者或研究者。项目公开介绍应解释这一背景。

## 2. 核心目标

- 将研究过程组织为可暂停、可审查、可恢复的项目工作流。
- 让文献、方案、代码、数据、实验、结果和稿件版本相互关联。
- 通过模块支持不同研究方向、期刊格式和 Agent 的扩展。
- 在本地调用 Codex CLI，在用户配置的远程 SSH 主机上运行全量实验。
- 让生成的研究方案、实验报告和论文初稿能追溯到来源与运行证据。

## 5. MVP 不做的事

- 不承诺自动选题、自动证明创新性或无人参与地发表论文。
- 不在 MVP 实现多研究方向代码插件 SDK。
- 不在 MVP 实现 Claude、DeepSeek harness 等其他 Agent 适配器。
- 不把投稿目标推荐塞进期刊格式插件。
- 不建设 AutoDL 专用 API 集成；先用通用 SSH 流程。
- 不集成机构订阅、不批量抓取 Google Scholar、不自动下载受限全文。
- 不把大型数据集纳入 Git，也不在首版定死其传输技术。
- 不拆分微服务，不建设多租户 SaaS。

## 6. 开发原则

1. **项目数据是事实来源。** 对话只是交互记录，不代替结构化研究对象。
2. **结论关联证据。** 文献判断关联来源位置，实验判断关联运行和产物。
3. **主流程由平台控制。** Agent 提建议和产物，平台保存状态、版本和审批。
4. **执行器与 Agent 分离。** 本机 Codex 做研究辅助；SSH Runner 执行远程实验。
5. **先用配置验证模块边界。** MVP 不为了“可扩展”提前造任意代码插件系统。
6. **承认不确定性。** 未验证、证据不足、相互矛盾的内容必须能明确表达。

## 7. Codex Skill 参考

Codex Skill 采用目录形式，核心文件为含 YAML front matter 的 `SKILL.md`，可附带脚本、引用文档和模板。项目级 Skills 放在 `.codex/skills/<skill-name>/SKILL.md`。Skill 说明可复用的工作方法；实际项目数据与工具仍由平台提供。参考：[OpenAI Developers: Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills)。

## 8. 开发

需要 Node.js 22.12+ 与 pnpm 10。安装依赖后，可运行：

```sh
pnpm install
pnpm typecheck
pnpm test
pnpm build
pnpm dev
```

`pnpm dev` 构建并启动简体中文 localhost Web 工作台，当前开发分支默认访问 `http://127.0.0.1:22223`。界面、热更新和 `/api/v1` 请求共用一个端口，不再启动独立的内部 API 监听或前端代理。`pnpm start` 同样在 `22223` 提供已构建界面和业务接口。可通过 `TRASH_PORT` 覆盖统一端口；端口被占用时直接报错，不会自动换号。工作台提供当前默认配色和蓝色科技风两种主题，选择保存在当前浏览器中。当前可创建持久化项目、导入 PDF/BibTeX/RIS/Markdown/公开网页、通过 OpenAlex 搜索文献，并按全文检索结果回到页码或段落定位；Google Scholar 仅打开用户触发的浏览器搜索。文献元数据和用户内容保留原文。项目数据默认写入操作系统用户数据目录下的 `trash` workspace，可通过 `TRASH_HOME` 覆盖。网页正文只在用户明确提交 URL 后抓取，拒绝私网目标并限制响应大小和跳转。全文检索使用 SQLite FTS5，向量检索尚未纳入本阶段。

项目对象协议位于 `packages/protocol`，当前协议版本为 `v1`。选型和 Phase 0 脚手架见 [ADR 0001](docs/adr/0001-phase-0-tooling-and-protocol.md)；Phase 1 持久化、导入和检索边界见 [ADR 0002](docs/adr/0002-phase-1-local-literature.md)。

## 实验模块（待集中验证）

项目“实验”提供本地 Git 仓库管理、已有 AutoDL 实例的 SSH 配置、计划版本、远端持久任务与产物关联。密码仅保存在本机服务内存，首版不操作 AutoDL 网站或开关机。操作、指标格式和限制见 [实验模块说明](docs/12-experiment-module.md)。本模块尚未测试、未连接实机，不代表真实运行闭环已验收。

### 本机 Codex 开发入口

项目“实验 → 代码”绑定仓库后，可使用“本机 Codex Agent”提交代码任务、选择权限、查看回复和事件、取消任务。当前直接调用运行 TRASH 的 WSL / 本机 Codex CLI，沿用本机登录和模型配置；每次独立任务，不是交互终端。实现尚未测试或真实模型验收，操作及边界见 [WSL Codex 开发 Agent](docs/16-wsl-codex-agent.md)。

### 项目 Agent 对话

“任务”右侧新增“Agent 对话”，支持项目级历史消息与 Codex 会话续聊，可通过平台工具读取文献、修订卡片/Wiki、登记真实实验结果，并在项目目录编辑论文草稿。未绑定代码仓库也可使用。实现尚未测试，详见 [项目 Agent 对话说明](docs/17-project-agent-chat.md)。

### 文献自动分析

文献页提供“Agent 分析”按钮，依次生成文献卡片与主题 Wiki，并显示进度、失败数量和停止入口。内容保存为待审版本，真实模型流程尚未测试，见 [文献 Agent 分析说明](docs/19-literature-agent-analysis.md)。

### 文献复现部署环境分析

在“文献复现”选中论文代码后，点击“分析部署环境”，本机 Codex CLI 会按项目 Skill `trash_analyze_code_environment` 只读分析筛选后的代码文本。可在“部署环境报告”查看依赖、依据行号、建议命令、历史报告及代码变化提示。建议命令不自动执行，报告均标记未运行验证。

报告下方可选择已连接 AutoDL 主机和 Python 解释器进行只读对照；不自动连接、安装依赖或运行论文模块。CUDA/驱动与复杂版本条件保持待确认。本机需要 Python 3 和已登录的 Codex CLI；可用 `TRASH_CODEX_COMMAND` 指定 CLI。新接口需要重启后端加载。

所有自研 Skill 位于项目 `.agents/skills/`，目录和 `name` 必须以 `trash_` 开头，不修改全局配置。实现与尚未执行的验收清单见 [环境分析交付记录](docs/61-environment-analysis-delivery.md)。

### 从分析报告运行复现实验

“分析源代码”使用项目 Skill 2.3.0 识别各数据集的路径、运行阶段与结果采集规则。“跑实验”可逐项绑定平台数据集，确认方案后串行执行，显示真实阶段进度并将有效指标收集到“数据 → 实验数据”。旧报告可继续查看，自动配置需要重新分析。实现尚未运行验证，使用方式与验收范围见 [自动复现实验交付记录](docs/124-automatic-reproduction-experiments.md)。


“跑实验”新增从头训练、已有权重评估、完整检查点继续训练的模式选择，权重可浏览远端文件或选择已记录的模型产物。资源改为读取主机 CPU/GPU 选项，展示型号和显存，无需手写设备编号。需要重启后端并使用 Skill 2.4.0 重新分析；尚未运行验证，详见[运行模式与资源选择](docs/126-experiment-modes-and-compute-resources.md)。
