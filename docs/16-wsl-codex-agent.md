# WSL / 本机 Codex 开发 Agent

## 入口与范围

进入项目 → 实验 → 代码，绑定本地 Git 仓库后使用“本机 Codex Agent”。输入任务，选择权限与运行时限，核对目标目录并勾选本次执行授权，点击“启动 Agent”。“检测 CLI”仅执行版本探测，不调用模型。

TRASH 当前运行在 WSL Ubuntu-24.04，直接启动同一环境 PATH 中的 codex，不经过 Windows 转发。平台进程沿用启动它的用户环境、Codex 登录与模型配置；不读取、复制或保存认证文件。模型留空使用 CLI 配置，也可为单次任务指定模型。如果服务找不到命令，可在启动服务时设置 TRASH_CODEX_COMMAND 为可执行文件完整路径，不需要修改全局 Codex 配置。在 Windows 原生 Node 下启动不自动切换至 WSL，应在已配置好 Codex 的 WSL 终端启动 TRASH。

与既有文献 Agent 区别：文献 Agent 读取资料快照并生成待审卡片/Wiki；开发 Agent 的工作目录是真实绑定仓库，可按授权读写代码、执行命令，回复不要求固定 JSON。它不自动把代码修改转为实验计划，也不自动启动 AutoDL。

## 权限与执行

- 默认 workspace-write：项目目录读写；另有只读分析及完整本机权限可选。
- 完整本机权限为 danger-full-access，可能访问仓库外文件与网络；界面明确展示说明，每次启动需确认。它不是“只在仓库内的完整权限”。
- 使用 codex exec 的非交互模式、JSONL 事件与命令参数数组；approval_policy=never 仅为本次启动参数。超出所选权限的动作不能交互提权，不自动放宽权限，不使用绕过沙箱与审批的快捷参数。
- 不覆盖本机模型、Skill、MCP 或认证设置，但这些能力是否可调用仍取决于本机 CLI 配置、信任设置、工具及所选权限；不能等同于本开发对话额外提供的工具。
- 默认提示词要求读取 AGENTS.md、保留已有改动、未经明确要求不测试、不提交、不推送、不合并、不改全局配置。用户可以在每次任务中明确要求验证或提交。提示词约束不是宿主系统权限隔离，尤其完整本机权限不提供目录隔离保证。

## 记录、取消与恢复

每次任务独立执行，使用 ephemeral，不复用用户已有 CLI 会话；当前不是交互终端，不支持中途输入、审批对话或 CLI 会话续聊。代码文件本身保留在仓库中，可用下一次任务继续开发。

记录版本、模型、权限、实际目录、用户任务、开始/结束、退出码、回复、事件和前后 Git 状态。执行事件最多约 1 MiB 字符，超限标为截断；回复也设上限。任务记录放在项目工作区 code-agent 目录，以 JSON 原子替换写入，权限 0600；不写入绑定代码仓库，不提交平台代码库。常见凭据格式会脱敏，但不保证过滤所有输出，所以不要将密钥或密码写入任务、代码或工具输出。

页面轮询展示日志与结果。关闭页面不取消本地进程；取消或超时对进程组先发送 SIGTERM，再按需 SIGKILL，等待退出后解除占用。保留改动，不自动 reset、清理或提交。CLI 退出码和 turn.failed 均参与失败判断，完成只代表任务进程成功，不代表测试或科研验收通过。

同一绑定仓库在平台内串行执行，执行期间阻止绑定/提交操作、新实验提交/重试及项目删除，已有外部编辑器与独立终端不受此锁控制。未结束实验阻止同仓库 Agent 启动。服务重启后旧任务标记中断，不自动重跑或根据旧 PID 杀进程；请核对旧进程确实停止和仓库改动，再在原项目的任务记录中点击确认解除。该确认不由平台冒充进程存活检测。

任务记录会随本地项目文件删除，不参加现有知识包导出。需要保留完整开发历史时备份本地工作区；既有文献任务与远端实验运行记录保持独立。

## API

项目级 `/api/v1/projects/:projectId/code-agent` 下：

- GET detect：本机 CLI 版本与 WSL 环境信息。
- GET tasks、GET tasks/:taskId：任务列表摘要与任务详情。
- POST tasks：instructions、model、sandbox、timeout_seconds、confirm=true。
- POST tasks/:taskId/cancel、tasks/:taskId/acknowledge：confirm=true；后者仅解除已人工核对的中断状态。
