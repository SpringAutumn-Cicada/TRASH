# Agent 任务页设计方案

本轮只提供设计，不修改产品页面。效果图为视觉提案，实际数据以平台为准。

## 先选色系

| 版本 | 配色 | 气质 | 建议 |
|---|---|---|---|
| A 雾紫 Focus | 主色 #7654BB，强调 #8D6DD6，背景 #F7F5FB，正文 #252334 | 克制、轻盈，与现有 Wiki 一致 | 首选，降低跨页面割裂感 |
| B 青瓷 Clarity | 主色 #287B78，浅底 #EAF3F0，背景 #F5F8F7，正文 #203234 | 安静、清晰，长时间阅读友好 | 如果希望任务区与 Wiki 有区别 |
| C 石墨 Console | 侧栏 #242633，强调 #9170CB，背景 #F6F6F8，日志白底 | 专业，强调监控与执行 | 适合偏工具控制台的方向 |

## 共用信息架构

1. 页面标题、搜索和状态筛选压成紧凑两行，减少说明文字。
2. 左侧任务队列占23%，右侧详情占77%；左右分界支持拖动，队列也可收起。
3. 左侧每项只保留两行标题、一行状态/阶段；排队原因按需显示，避免逐条重复“等待前序任务完成”。
4. 右侧标题最多两行，状态、耗时、最后活动时间合为一行；停止操作为小型描边按钮。
5. PDF 阅读进度独立成紧凑重点区：8/18页、44%、当前第9–12页、批次3/5；五段进度条对应实际批次，最后一批只有两页，百分比按页数计算。完成段实色、当前段浅底带轮廓、未开始段灰色。不用虚构的时间进度。
6. 保留细阶段导航：PDF阅读 → Wiki生成 → 发布，PDF页数不是全任务百分比。是否正在发布及是否完成均依据真实阶段事件。
7. 日志占右侧可用高度至少60%，页面固定可视高度，日志内部滚动；顶部信息不再挤占一半屏幕。
8. 执行日志/生成结果/任务信息一层标签；进度/原始输出、复制、放大收在同一紧凑工具行，减少双层大导航。
9. 日志时间戳固定列，正文自然换行。区分完成、当前活动、警告和失败；普通事件不逐行放大卡片或粗分隔线。
10. 底部小状态栏保留自动跟随、已加载条数和连接状态。用户滚动上翻时暂停跟随，出现“新日志12条”入口。
11. 失败时在日志顶部提供具体原因与从断点继续，用户停止不自动重启。等待连接与任务执行分开表达，界面不假装知道模型内部思考状态。

## 视觉与交互

正文14px、日志13px、时间戳12px，任务标题18–20px。8px基础间距，面板圆角10–12px，细滚动条，边框比阴影优先。颜色只表达主操作、选中、进度和状态，正文保持深色。绿色成功/琥珀警告/红色失败三个语义色不随主题改变。

屏幕小于1100px时队列缩窄；小于800px时任务选择变成可收起列表，日志优先展示。保留键盘焦点与可读对比度，不依赖颜色单独表示状态。

## 推荐

推荐 A 雾紫：保留现有 Wiki 紫色视觉语言，但任务页用白底日志、轻紫进度和更少容器边界，避免全屏铺紫。先确定色系，再确认日志占比与进度样式，最后实施。
