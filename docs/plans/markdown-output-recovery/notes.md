# Markdown 输出校验与恢复

第一阶段：逐项检查目标文件，区分缺失、空文件、大小超限、路径异常、格式及来源错误。任务目录 output-check.json 保存逐文件校验结果与有效草稿哈希；错误列出全部问题。统一生成提示中的三卡片与单篇 Wiki 说明。

开发自验：代码审阅、git diff --check；未运行测试、lint、额外类型检查或浏览器验证。用户验收待执行。运行记录不提交。

第二阶段：继续分析时校验原始资料、指令、依赖、目标版本和 skill 哈希，恢复合格且有变化的草稿；已有检查点时核对文件哈希，旧任务无检查点时独立校验。保留合格草稿，只生成待补文件；输出不合格自动补救一次，不重读 PDF、不增加总超时。路径安全错误不自动修复。CLI 报告错误不再仅按退出码零误认为成功。无论生成是否正常退出均记录检查点并保护已有合格草稿。全部输出合格且发布版本未变化后整组提交。

生效与验证：按本分支持久授权运行 pnpm build；构建成功（Vite 有既有的大 chunk 提示）。发现运行中知识任务及排队任务，暂不重启以免中断；服务仍使用旧后端逻辑，需任务结束后重启生效。未调用真实模型、未执行功能测试或浏览器验收。用户验收待完成：缺失补写、格式修复、超限压缩、继续分析复用、版本变化保护。

交付时只读检查：现有服务 /api/v1/health 返回 200；knowledge_tasks 有 1 个 running、9 个 queued，因此没有执行重启，没有重跑已有任务。最终修改后 pnpm build 再次成功；此检查不等于新逻辑已上线或模型补救功能已通过验收。
