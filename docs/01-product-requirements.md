# 产品需求与范围

- 文档版本：0.1
- 状态：基于用户已确认决策形成的需求基线
- 项目简称：`trash`

## 1. 产品定位

`trash` 是面向个人研究者与小型研究协作的本地科研工作台。它把研究问题、文献、研究方案、代码、实验、结果和论文稿组织在同一项目中，通过可插拔的研究方向模块与 Agent 适配器完成研究辅助和任务执行。

首版以 APT 检测与溯源研究为试点，验证从文献调研到实验报告和论文初稿的闭环。平台是研究辅助工具，不能替代研究者确认创新性、实验设计、结果解释、引用正确性和最终论文责任。

## 2. 用户与主要场景

### 2.1 首要用户

项目创建者本人。产品首先优化单人研究中的资料管理、实验组织、结果复查和稿件迭代。

### 2.2 次要用户

同学或小型课题组成员。后续可加入项目导入导出、共享项目和协作能力；多人权限不是 MVP 前置条件。

### 2.3 典型场景

1. 研究者创建 APT 研究项目，描述研究问题并导入论文。
2. 系统从文献和项目材料中生成有来源的相关工作整理及研究问题候选。
3. 研究者确认研究方案、基线、数据和评价指标。
4. 研究者在本地运行烟囱实验，或将全量实验提交到 SSH 远程主机。
5. 系统整理实验配置、日志、指标、图表和大型远程数据引用。
6. Agent 基于已确认方案与实验结果生成报告和论文初稿。
7. 研究者审阅结论、引用和期刊格式，修订后导出。

## 3. 产品概念

### 3.1 Workspace

本机工作区，包含应用配置、项目索引、SQLite/关系数据库文件（具体选择待定）、文献和产物目录、Git 工作区以及本地 Codex CLI 配置引用。敏感密钥不写入项目版本库。

### 3.2 Research Project

一个研究项目包含研究问题、模块配置、来源材料、方案版本、Git 仓库、数据引用、实验记录、结果、报告和稿件版本。一个项目绑定一个研究方向模块版本，允许模块升级但必须显式迁移。

### 3.3 Research Module

提供一个研究领域的阶段模板、数据 Schema、实验配置 Schema、指标定义、输出模板和检查规则。首版模块使用可验证的声明式配置，不执行任意第三方模块代码。

### 3.4 Agent Adapter

把平台的 AgentTask 映射到具体 Agent 的运行方式。MVP 使用本机 Codex CLI。后续 Claude、DeepSeek harness 等 Agent 通过适配器接入，不改变研究项目对象和研究模块协议。

### 3.5 Journal Module

基于分析阶段选定的投稿目标，提供格式、结构和投稿材料清单。它不负责推荐或判断投稿目标。

## 4. 工作流需求

项目阶段允许暂停、退回、分支和重新运行。每次阶段执行保存输入快照、输出、Agent/模型信息、时间、状态与人工确认记录。

| 阶段 | 输入 | 主要产物 | 必须由研究者确认的内容 |
|---|---|---|---|
| 问题与文献 | 研究兴趣、约束、导入文献、检索式 | 研究问题候选、文献矩阵、来源摘录 | 研究范围、关键来源、研究问题 |
| 选题分析 | 已确认问题、相关工作和缺口候选 | 选题分析、差异化假设、风险与可行性 | 研究目标及其合理性 |
| 方案设计 | 研究问题、文献证据、资源约束 | 假设、方法、基线、数据、指标、消融计划和成功判据 | 方案版本和实验设计 |
| 实验执行 | 已确认方案、Git 提交、数据引用、环境 | 实验运行、日志、配置、指标与产物 | 全量实验提交和资源使用 |
| 结果分析 | 实验产物、研究假设、指标定义 | 统计摘要、图表、误差和限制分析、投稿目标分析候选 | 结论解释、投稿目标 |
| 写作与审查 | 已确认方案与结果、引用来源、期刊模块 | 论文初稿、实验报告、格式检查结果 | 最终事实表述、引用、署名和导出 |

阶段完成不等于结论正确。项目应记录 `draft`、`needs_review`、`approved`、`rejected`、`blocked` 等明确状态；具体状态枚举在协议设计阶段冻结。

## 5. 功能需求

### 5.1 项目管理

- 创建、打开、归档和导出研究项目。
- 配置研究方向模块版本、Agent、Skill 集合、模型和权限。
- 展示阶段状态、近期活动、待确认事项、运行任务和成果。
- 提供历史版本与变更差异。

### 5.2 文献与知识库

- 支持用户导入 PDF、BibTeX、RIS、Markdown 和网页链接；首版必须明确列出实现的文件格式。
- 保存文献元数据、文件哈希、导入时间、来源 URL 与解析状态。
- 将用户导入材料纳入项目级 RAG，检索结果包含文件、页码/段落定位和原文摘录。
- 支持 Google Scholar 查询入口和用户辅助导入；不实现自动批量抓取。Google Scholar 官方帮助说明自动访问需遵守 robots.txt，且不提供批量记录访问：[Google Scholar Search Help](https://scholar.google.com/intl/en/scholar/help.html)。
- 公开文献检索服务通过 Provider 接口扩展；首批 Provider 的具体名单在实现前确定。
- 不连接机构订阅、校园代理或付费全文服务。

### 5.3 研究方案

- 将方案保存为版本化结构，包括假设、变量、数据、方法、基线、指标、消融、资源预算和判定规则。
- 每个关键设计选择可关联文献来源或人工说明。
- 方案变更不覆盖既有实验依据；新方案版本需重新关联实验。

### 5.4 实验执行

- 本地执行烟囱实验和轻量验证。
- 通过通用 SSH Runner 执行远程任务；远程主机由用户配置。
- 实验代码必须处于 Git 仓库，并以 commit SHA 作为代码版本基准。
- 保存命令、配置、数据引用、环境信息、日志、指标和产物清单。
- 远程任务支持提交、状态查看、日志跟随、取消、重连和产物回传。

### 5.5 写作与导出

- 基于用户确认的方案、实验结果和引用生成研究方案、实验报告、论文初稿。
- 论文主张和数值结果能回指文献或实验数据；没有证据的表述标记待审。
- 投稿目标是分析阶段产物；期刊模块依照已选目标执行格式、结构和投稿清单检查。
- 首版导出至少提供 Markdown 和适用的 BibTeX/引用文件；DOCX/PDF 格式需在 UI 和实现阶段确认其优先级。

## 6. 权限与信任边界

- Agent 默认对当前项目工作区拥有完整读写权限，用户可调整权限配置。
- 权限按执行目标区分：本机项目工作区权限与远程 SSH 主机权限是两份独立配置。
- Codex CLI 由本机用户环境运行；平台不自行收集或上传 Codex 登录凭据。
- SSH 使用用户配置的连接信息和本机 SSH 能力；私钥内容不得写入项目文件、日志或 Git。
- 执行前展示项目、主机、Git commit、命令、环境配置和数据引用。
- 记录 Agent 发起的工具动作和平台执行结果，便于复查。

## 7. 非功能需求

- **可恢复：**本地 UI 关闭或网络断开后，已提交的远程任务仍可重新连接查看。
- **可追溯：**研究对象、Git commit、数据版本、任务和输出之间具有稳定关联。
- **可移植：**项目文件不依赖在线 SaaS 才能读取；导出时带必要元数据。
- **可扩展：**研究模块、Agent 适配器和期刊格式模块有各自版本。
- **可审查：**模型生成内容和用户确认内容可区分。
- **可维护：**MVP 为 TypeScript 模块化单体，避免微服务化。

## 8. MVP 验收标准

完整验收用一个 APT 研究课题验证：

1. 新建项目并选择 APT 模块，录入研究问题和资源约束。
2. 导入文献，检索项目材料，并能从摘要或写作建议定位回文献页码/段落。
3. 生成结构化研究方案，研究者确认后保存版本。
4. 在项目 Git 仓库提交代码，并以 commit SHA 创建实验任务。
5. 本地运行烟囱实验；用通用 SSH 将全量任务提交到用户创建的 AutoDL 主机。
6. 初始化脚本验证远程环境且不覆盖用户选择的基础环境。
7. 查看远程任务状态和日志；结束后回传日志、配置、指标、图表和报告。
8. 对大型原始数据只保存远程引用及校验信息。
9. 从确认过的方案和结果生成实验报告与论文初稿，未支持的主张能被标出。
10. 选择期刊模块后完成格式、结构与投稿材料清单检查，不生成投稿目标推荐。
