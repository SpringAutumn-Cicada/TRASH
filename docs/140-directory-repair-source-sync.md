# 目录修复落实源码适配与远端同步

分支 ct_dev_test，基线 a70ce24。开始工作树干净，核对近期及相关文件历史、依赖目录及项目规范检索记录，无适用 AGENTS.md；使用 skill-creator 指导更新项目 Skill。

## 原因与改动

旧目录诊断明确要求只修正报告、禁止补丁，Agent 正确判断路径适配缺失后只能 blocked；继续只生成同类报告。现允许复用本地适配机制输出有原文及 SHA-256 依据的最小路径补丁，由平台备份导入副本、唯一定位应用、重新采集与分析。算法、模型、划分不改；外部文件缺失或无可靠改法仍阻塞。

新报告复核 ready 后，通过同一任务的 changes.json 获取确切修改前后内容。远端同步先核对整份源码清单：未改文件必须与报告 SHA-256 相等，待改文件必须与本轮补丁原文相等，已同步的文件跳过。兼容上传展开一个外层目录的布局。任一无关修改、缺失文件或不安全路径都会在写入前拒绝。

写入前把所有待改原文及 before/after 哈希清单保存在远端代码目录的 .trash-directory-repair-backups/<task>/ 下，再逐文件用同目录临时文件替换，保留权限，最后完整复核报告清单。发生中断保留原文备份，继续时按 before/after 哈希识别未同步与已同步文件，不重复覆盖。该批文件不是整体原子提交；中断后可能部分同步，复查通过前不宣称完成。

继续已完成本地适配的任务时复用该报告和同步状态，不重新生成另一套补丁。旧 blocked 且未适配的任务会启动新分析，使用更新的适配指令。之后沿用默认权重核对/补传与目录复查，成功才采用新报告并允许重新确认实验。

## 真实进度

源代码分析卡未执行适配时不再把“本地适配／复核代码”计入完成阶段。目录修复在分析任务结束后展示“分析报告已生成”及实际适配状态，外层阶段为分析适配、备份同步、权重、目录复查；受阻停在实际阶段，不再用分析 7/7 表示整体修复成功。

## 开发自验、用户验收与遗留

实际只做 Git/依赖目录检查及源码差异审阅，未执行测试、lint、类型检查、构建、浏览器、Skill 校验、真实 Agent、远端同步或实验。用户验收待执行。重点集中核验：旧 blocked 任务继续、本地补丁与新报告、展开目录映射、远端原文变更拒绝、备份完整性、部分同步中断恢复、权重补传、复查与真实进度。

同步命令执行中取消会等待当前命令结束，保留已完成同步及备份，之后阻止继续阶段。预处理仍由报告的独立步骤在确认实验后执行，目录检查不启动训练。复杂非路径源码改动及缺失外部数据仍给阻塞原因，不保证任意项目自动修好。

本次未重启、推送、合并或修改全局配置。更新后重启服务并刷新，再继续原失败任务。
