## 原因与修改

上传前弹窗的 freshness 使用 analysis-snapshot，与报告一致；真正上传使用 snapshot，包含分析故意排除的图片、二进制、data/vendor 等内容。后端 assertUploadReady 原先将完整上传文件清单哈希直接与分析源码清单哈希比较，因此源码不变也可能被拒绝。

归档脚本抽取公共 analysis_reason 与 ANALYSIS_DIRS，分析筛选与上传清单投影共用规则。归档时记录 analysis_files，沿用同一批实际写入 ZIP 的文件 SHA-256、路径及大小；上传门槛比较该源码清单指纹，不另做存在时间差的扫描。完整 files、ZIP SHA-256 和远端包校验不变。源码增删改仍导致拒绝，适配报告 ready 的门槛保持。旧报告无需仅因此重新分析；旧快照缺少 analysis_files 时沿用原完整比较，不无条件放行。
