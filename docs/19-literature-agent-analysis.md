# 文献 Agent 分析按钮与自动知识归纳

## 操作

项目 → 文献，点击“Agent 分析”。该操作调用本机 Codex，会消耗用户本机配置的模型服务额度。按钮旁明确显示“分析文献 → 生成卡片 → 归纳知识 Wiki，使用本机 Codex，生成内容待审”。用户点击即提交这次分析，不额外弹确认框。

按钮区域显示阶段、卡片/Wiki 成功数量、失败或取消数量、跳过数量，提供停止分析及卡片、Wiki、任务日志入口。网页关闭后本机服务继续执行，回到文献页可恢复读取进度。不会因导入文件自动启动分析；每次需由用户点击。

## 流程

1. 选取当前项目全部具有非空解析正文或摘要的文献。只有标题等元数据的文献跳过，全部不可读时显示提示，不创建空 Wiki。
2. 每篇文献创建独立文献卡片任务，读取原有正文/摘要、项目研究问题及既有卡片版本。归纳问题、方法、贡献、局限、实验条件和可借鉴思路，要求来源定位，不能编造内容。仅摘要时明确范围。
3. 卡片任务全部结束后，使用成功输出的具体对象版本生成知识 Wiki。为每个新输出记录 output_version，避免归纳时无意引用后来被修改的版本；旧任务缺少该字段时沿用已有兼容读取。
4. 成功卡片超过 100 个时，按每组最多 100 个先生成分组 Wiki，必要时继续分层归纳，保持每次 dependencies 不超过协议上限。
5. 生成五个主题页：文献知识总览、研究问题与背景、方法与技术路线、数据集与评价方案、研究思路与待验证假设。卡片/分组输出作为固定 dependencies，保留来源和知识对象引用。同标题 Wiki 创建修订候选，不覆盖历史或自动采纳。

所有内容仍经过既有 schema、证据检查与乐观版本校验，以 agent 身份保存待审。失败、取消或缺失结果不伪装为有效知识；部分卡片成功时允许继续归纳并显示部分完成，全部卡片失败则停止。未分析到的材料不能被推测或编造。已生成内容可从卡片和 Wiki 页面查看、编辑、审核。

## 队列、取消与记录

复用文献 KnowledgeAgent 的项目串行队列、任务日志、取消与超时。项目已有活动分析时重复启动返回当前进度。停止只取消本次流程的活动子任务，保留已完成版本，不取消无关任务。单个卡片或 Wiki 任务时限 900 秒。

终态后再次点击可发起新分析，沿用原有指纹去重规则；存在新输入或已有候选时可能生成新的待审版本，不承诺每次点击都跳过已分析文献。此版没有“只分析新增”选项，也不自动重试失败任务。

流程阶段及子任务 ID 保存在 projects/:id/literature-analysis/current.json，并按 analysis ID 保留记录；具体任务仍在数据库 knowledge_tasks 中。服务重启将流程标为 interrupted，不自动重新调用模型，用户重新点击时保留已有产物。流程不参与现有知识包导出；知识包仍可导出已生成知识版本。

项目有开发/对话 Agent 占用时拒绝启动分析；项目有排队或运行知识任务时拒绝启动开发/对话 Agent，减少相互编辑造成的版本冲突。用户手动编辑仍保留版本冲突保护。

接口为项目级 GET literature-analysis（状态）、POST literature-analysis（启动）和 POST literature-analysis/cancel（停止）；POST 均要求 confirm=true。接口使用现有项目归属与本机访问约束，不改全局 Codex 配置。命令沿用 codex 或 TRASH_CODEX_COMMAND，生成期间只读材料，由平台保存校验后的输出。
