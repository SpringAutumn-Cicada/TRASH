# 部署失败自动分析

部署确认失败后调用一次本机 Agent，只读取脱敏失败上下文、原安装方案、环境报告及筛选输入，生成原因、具体依据、解决建议和待确认事项。原部署卡片展示分析进度与报告，保留原始错误和安装日志；不会自动重装、更改版本或修改远端环境。继承现有 CLI 默认配置，不修改全局配置。每次失败分析消耗 token，最长十分钟，不自动重试。

分析中阻止继续/修复并持续刷新。分析失败、CLI 不可用或输出格式不合法单独显示，不能覆盖原部署错误或宣称安装成功。重启时将未完成分析标为中断。断线后的远端状态必须先刷新确认失败才触发分析；已有远端失败记录没有报告时，在连接原主机后读取部署列表也会补充分析。取消和状态未知不自动调用 Agent。继续部署是新的一次尝试，可生成新的失败报告；手动 Agent 修复部署仍按原行为执行。

分析只依据已有材料，不联网确认分发包；日志不完整或缺少实际主机信息时必须列为待确认，不能猜测冲突或虚构 wheel 来源。进一步采集和官方来源确认仍使用 Agent 修复部署。约束与请求相同版本重复出现不是冲突，缓存不等于安装完成。

交付分支 ct_dev_test；依赖目录存在，开始工作树干净。开发自验为阅读代码与差异；未执行 lint、类型检查、测试、构建、浏览器、真实 Agent 或 SSH 验证，用户验收待进行。需要重启后端（pnpm dev 模式重新启动并刷新页面）；本次未重启、推送或合并。
