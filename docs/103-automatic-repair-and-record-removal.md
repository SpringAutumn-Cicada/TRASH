# 失败后修复并继续与部署记录删除

确认远端安装失败后，先输出只读分析报告，再自动进入现有 Agent 修复流程。原报告、主机、目录、解释器和部署记录 ID 保持一致；重新采集实际主机环境，Agent 查阅官方来源并生成具体安装组，平台校验原依赖约束、HTTPS 来源及新源依据后执行。修复方案展示原因、步骤和来源。保留 venv，将旧安装方案断点身份迁移到校验后的修复方案，重新核对各组，跳过已满足的直接依赖；未完成组由 pip 重新尝试，不保证下载字节断点续传。

每次部署最多自动修复一次，手动修复不额外自动修复；修复仍失败、分析未完成、缺少原报告/方案或远端状态未知时停止，展示报告及手动处理建议。未知任务先刷新确认停止。分析阶段可以停止分析与自动修复；不会因取消而继续安装。分析报告输出使用独立文件保留历次材料。安装组实际状态仍由 runner 和 pip check 决定，不把建议当作成功。Agent 生成方案及分析消耗 token，安装进度由脚本采集。旧轮询响应不能覆盖下一次远端任务状态。

已完成、失败或取消的部署卡片提供删除记录按钮及就地确认；不要求 SSH 在线。服务端拒绝正在执行、分析中或远端状态未知的记录删除。删除仅将本地记录 JSON 移入 archived，任务目录和报告保留用于恢复排查；不删除远端代码、venv、依赖、日志和断点。列表不再显示该记录，不能从列表直接继续已删记录，原方案材料仍留存本地。
