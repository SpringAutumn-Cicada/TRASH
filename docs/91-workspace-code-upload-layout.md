# 工作区代码上传与运行路径联动

文献复现上传弹窗读取所选主机的项目工作区，默认使用 root/reproductions/复现名称，提前展示源码与 .venv 路径。ZIP 保留原名，匹配 ZIP 名的单一包装目录展开一层，多顶层目录保持原结构。目录名保留中文、过滤特殊字符并限制 UTF-8 字节长度。已存在目标不覆盖。已保存工作区的用户可显式取消规范模式改用父目录；未配置工作区时仅有历史上传的代码允许沿用旧目录，新上传提示先设置工作区。

实验代码增加上传弹窗，选择主机与实验名称，自动定位 root/experiments/实验名称。上传前后检查 Git 工作树与 HEAD，使用受控源码快照，上传 SHA-256 校验、解压和取消清理复用已有流程。保留实验上传路径、提交与快照记录，不创建伪造的文献复现条目。源码归档忽略 .venv、venv、node_modules、datasets、weights、checkpoints、outputs 等环境与产物目录。data 目录未统一排除，以免误删以 data 命名的源码包；共享数据应放工作区 datasets。

部署默认目录继续取实际上传记录，一键部署创建该目录下的 .venv，不按新规则猜测旧上传位置。已有部署任务和旧上传记录不迁移。实验运行保持快照隔离执行，新提交运行落到 root/outputs/reproductions|experiments/方法名/run_ID；每次运行内部的日志、代码副本及产物沿用既有 runner 格式。未配置工作区的旧项目继续使用原运行路径，已有运行位置不变。

上传、部署或活动实验期间不能修改工作区配置。失败或上传中的数据集不能新建为运行计划的数据输入。数据模块与原计划复用同一数据集对象。

交付：ct_dev_test，本阶段独立提交。仅静态审阅改动、接口参数和清理分支；按用户规则未执行 lint、类型检查、测试、构建、浏览器、Python 归档脚本、真实 SSH 或部署。用户验收待执行，包含同名保护、ZIP 包装层、跨主机配置、失败及取消、断线清理、旧目录和 venv 路径。需要停止旧服务重新 pnpm dev 再刷新；本次未重启、合并或推送。
