# 终止上传后清理远端目录

分支 ct_dev_test，基于 cfa91ad。开始时工作树干净，已核对上传取消、SFTP 与相关历史，依赖目录存在。

按本轮要求，上传取消在实际传输停止后清理本次新建的远端子目录。记录本次 mkdir 成功返回的唯一目录，绝不把用户选择的父目录或已存在跳过的目录作为删除目标。SFTP 取消等待本次通道 close，再开启独立 SFTP 清理；共享 SSH 与终端保持连接。

取消仍只接受快照准备、远端准备及传输阶段，不允许解压开始后取消。因此清理仅 unlink 本次 ZIP、rmdir 空 code 目录及 rmdir 本次根目录，不运行递归 rm；检查根目录不是符号链接且直属选定父目录。若意外出现其他文件、权限错误或 SSH 中断，清理失败保留剩余文件，并在上传弹窗中显示残留路径，不报已清理成功。不删除本机代码、历史快照或之前成功上传目录。

快照阶段尚未创建远端目录则直接终止，无目录可清理；准备阶段取消等待当前操作返回再清理。服务端保留项目锁至清理结束，UI 持续显示正在终止，避免关闭或重复上传产生混淆。先前文档中的“取消保留远端残留”由本次自动清理规则替代；清理失败仍需人工处理。

实际仅源码阅读与编辑，未运行 lint、类型检查、测试、构建或浏览器验证，未连接 AutoDL 或删除实机文件。尚未测试，用户验收未执行。待集中验证传输关闭/清理顺序、取消阶段竞态、空目录清理、附加文件保护、权限失败/断线提示及共享终端保留。未合并、未推送、不修改全局配置。
