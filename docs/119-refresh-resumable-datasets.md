# 刷新后自动恢复数据上传

新后台数据上传先将 File 与任务参数保存到同源 IndexedDB，写入事务完成后才发起网络上传；保存阶段明确显示“等待完成后再刷新”并保留离站提醒。站点存储不支持或配额不足则停止，不降级成不可恢复的上传。增加浏览器剩余存储预估（实际写入失败仍单独处理）。保存完成后，刷新重新打开同一浏览器配置与同一访问地址，会枚举待传记录并自动恢复，不要求重新选文件。清除站点数据、无痕窗口销毁、浏览器主动回收存储或换域名/端口无法保证恢复；本功能不是这些外部数据丢失情况的备份。

新增 dataset-upload-sessions 服务与接口，8 MiB 顺序分片；服务端项目数据目录保存 session.json 和 file.part、已确认 offset。每片用流式写盘、大小上限与偏移校验，完整收到且元数据保存后才确认；中断未确认片先截断回旧 offset，恢复最多重传一片。并发分片锁拒绝重复写。相同任务ID/参数可幂等恢复，冲突参数拒绝。收齐后 finish 仅启动一次原校验/SFTP流程并立即返回，真实传输不再依赖浏览器响应连接。前端轮询状态及数据集记录，刷新恢复后端阶段进度。取消支持未收齐的本地分片及正在传输的原取消逻辑，解压/保存仍不可取消；成功清理分片文件与浏览器副本，失败保留恢复资料，关闭失败记录尝试清理服务器暂存。

任务状态保存到后端，接收阶段服务重启可继续收片；若重启发生在SFTP阶段，状态明确失败/中断而非宣称断点续传，需检查原目录后新建上传，本次不实现SFTP字节续传。上传未完成时保护项目不被删除。存储成本增加：浏览器保留一份文件，后端保留分片暂存，原校验传输阶段还会创建原流程临时副本，需要足够磁盘空间。关闭浏览器时浏览器→后端分片暂停，重新打开后继续；服务端已收到文件则可继续SFTP。完成/失败均显示实际状态，不把关闭提示当成通过。
