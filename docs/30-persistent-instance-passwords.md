## 行为

添加实例、编辑密码或补充认证凭据时，密码加密保存到当前 TRASH 数据目录的 private/ssh-credentials 下。默认 Linux 数据目录为 ~/.local/share/trash；指定 TRASH_HOME 时跟随该目录。后端重启后按实例 ID 自动读取，连接终端、环境诊断、实验运行及编辑弹窗均复用已保存密码。退出页面或关闭服务只清空内存，不删除已保存密码。私钥口令仍仅存内存，SSH Agent 行为不变。

采用 Node 内置 AES-256-GCM，每次写入随机 IV，实例 ID 作为附加认证数据，密文记录版本、IV 和认证标签；文件名为实例 ID 的 SHA-256。密码文件采用临时文件及原子重命名更新。设备密钥随机生成，目录权限 0700、密钥和密文文件 0600。不写入项目数据库、浏览器存储、日志、项目文件或导出内容。设备密钥丢失或密文损坏时明确报错，不静默生成替代密钥覆盖已有凭据。

这是本机保存方案：密钥与密文由同一操作系统用户管理，不能防御该用户账户或整机被控制。迁移设备时需保护整个私有凭据目录，不将其作为项目资料分享。凭据存储文件仅在实际保存密码时生成，本轮没有创建真实凭据或密钥文件。

修改连接目标时沿用现有要求提供对应密码的规则；删除实例或项目时清除关联加密凭据。旧版内存密码不能从已经关闭的服务恢复，需要更新后再输入并保存一次，后续重启不必重填。界面同步移除“重启需重新输入密码”的旧说明。本记录替代旧文档中“密码仅保存在内存”的约定。
