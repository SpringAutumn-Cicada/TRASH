# TRASH 项目综合评估（2026-10-30）

## 评估范围与结论

本报告检查了 README、产品与架构等七份规格、两份 ADR、启动提示词、全部业务源文件、现有测试和 CI。以提交 c4fad6b 为基准；本次先做评估，不扩展业务功能。

项目已经具备本地项目与文献管理的首版实现，适合继续增量开发。距离“Agent 辅助科研并交付论文”的目标，主要缺口是工作流、Agent 执行、版本与审批、实验运行及论文证据关联。当前不能验收为完整写论文平台，也不宜按计划阶段数量折算完成百分比。

## 优先问题

以下区分直接代码事实与需进一步验证的风险；不将静态检查写成已完成攻击复现。

1. **运行版本声明冲突。** 根配置/README 声明 Node >=22.12，CI 固定 22.12.0；锁文件中的 pdfjs-dist 6.4.299 要求 >=22.13.0 || >=24。应统一支持的 Node 版本并在该版本重新验证，避免“本机能跑、CI 不满足依赖要求”。
2. **API 输入校验不统一。** readJson 的泛型只作类型断言；null、空白标题、非法 module、错误 limit 等没有统一运行时校验。Zod 错误不在 jsonError 的 400 映射中，部分非法输入会变成 500。应在 API 边界使用完整请求 Schema。
3. **导入过程缺少整体一致性。** saveArtifact 完成后再 createSources；后者失败时前者的文件和 artifact 记录不会一起回滚。需要导入暂存、成功提交、失败补偿及孤立文件清理。
4. **去重边界有限。** 文件按项目和内容哈希去重；OpenAlex 只对数据库已有结果去重，同一请求内的重复结果仍会生成多个 Source。缺少 DOI 归一化去重、网页重复导入处理及唯一性约束。
5. **中文检索能力需要专项验证。** unicode61 分词配合整条查询的短语匹配，不提供通用中文分词、子串或语义检索。现有测试主要覆盖英文术语，不能据此保证中文材料检索效果。
6. **来源文件的打开链路不完整。** API 返回片段而未提供原始文件下载/阅读接口；artifact 的 workspace URI 与物理文件布局不同，尚无解析器。显示页码不等同于在 PDF 阅读器跳转到该页。
7. **项目更新时间失真。** 导入文献没有修改 project.updated_at，列表显示的“更新时间”不能反映资料变化。
8. **本地服务请求边界需在 Agent 接入前加固。** 当前仅绑定回环地址，但无 Host/Origin 校验或本地会话令牌。现有网页抓取有地址校验与 DNS 固定等措施；这些不能代替对本地 API 的访问控制。应针对跨站写入、DNS rebinding 做验证和防护。
9. **解析资源控制不足。** 上传有 50 MiB 限制，网页有响应大小限制，但 PDF 解析没有页数、时间或并发预算；CPU/内存密集任务与 API 共进程。异常路径也应保证 PDF loadingTask 释放。
10. **试用与发布准备未完成。** E2E 默认沿用用户 workspace，测试创建的项目可能污染真实目录；应独立 TRASH_HOME。无项目导出恢复闭环；README 称开源但仓库未提供 LICENSE，发布前需确定许可证。

已有优点包括：项目检索隔离条件、SQL 参数绑定、来源哈希、来源定位、导入解析状态、原文与元数据区分、网页重定向重新校验和公开地址固定。应保留这些边界并补充失败路径验证。

## 建议开发顺序与验收

| 顺序 | 交付 | 验收方式 |
|---|---|---|
| P0 基线修复 | Node 版本、请求 Schema、错误映射、导入一致性、测试数据隔离、本地 API 防护 | 空环境安装与 CI；非法请求得到 4xx；失败无孤立数据；测试不写用户 workspace |
| P1 首个 Agent 闭环 | 任务/事件持久化、Adapter、超时取消、结构化输出、方案版本、人工确认 | 导入资料 → 生成有引用的方案候选 → Schema 校验 → 审阅确认；服务重启后记录保留 |
| P2 可复现实验 | Git 基准、DatasetRef、本地 Runner、日志指标产物 | 同一 commit 与配置创建独立运行；不完整输入阻止执行；失败原因可查 |
| P3 远程执行 | SSH profile、环境检查、持久任务、重连、轻量回传 | 可控环境测试后在真实 AutoDL 演练，断线可恢复，环境不被覆盖 |
| P4 写作闭环 | Claim/EvidenceLink、分析与稿件版本、引用审计、Markdown/BibTeX 导出 | 结果数值回指实验；文献引用回指来源；未证实主张标记待审 |
| P5 试用发布 | 项目备份恢复、安装说明、许可证与真实课题回归 | 新目录恢复项目并完成一个真实 APT 课题流程 |

下一批最有价值的业务交付是“基于已导入文献生成可审阅的结构化研究方案”，前置完成 P0。暂不增加多 Agent 编排、通用插件 SDK 或微服务；先验证一个研究任务从资料到方案的可靠闭环。
