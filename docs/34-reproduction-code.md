## 操作与版本

实验页导航新增“复现代码”，位于“实验代码”左侧；原“代码”改为“实验代码”。复用同一个目录树和带行号的只读预览组件。实验代码继续绑定 Git，复现代码完全不要求 Git。

每个项目可保存多份复现代码，支持 ZIP 导入和选择已解压的本地目录，可编辑名称、关联本项目参考文献、来源地址、备注。目录选择器在复现模式隐藏 Git 初始化选项且始终传 initialize_git=false，原实验仓库选择行为不变。顶部选择器切换论文代码，提供复制目录路径供本地编辑器打开。切换实验内页签保留页面状态。

ZIP 导入使用本机 Python 3 标准库解压至 TRASH 数据目录 projects/<项目>/reproductions/<代码 ID>/code，记录元数据保存为同目录下的独立 JSON（临时文件原子重命名），不修改数据库结构。绑定本地目录只保存规范化路径、不复制原目录。移除记录保留本地代码和快照；删除整个项目仍按现有规则清理项目托管文件，不会递归删除绑定的外部本地目录。不能移除活动实验使用的复现记录，导入/快照/上传期间阻止删除项目。

ZIP 保留原始目录结构，不自动去掉顶层文件夹；实验命令需按真实路径填写。压缩包与解压总大小上限 200 MiB，条目上限 20000；拒绝路径越界、反斜杠、特殊文件、符号链接、加密及重复条目。预览限制为 1 MiB，二进制不作文本展示；路径访问限制在绑定目录内。

每次创建计划或手动上传前生成独立 ZIP 快照，记录文件清单、大小与逐文件 SHA-256、ZIP SHA-256、关联文献和时间。不依赖 commit。快照忽略 .git 与 __pycache__，拒绝符号链接、特殊文件、常见凭据文件和过大目录，不默认上传数据集。快照和清单保存在 projects/<项目>/reproductions/snapshots/<快照 ID>，后续本地修改不影响已有快照。

## 上传与运行

“上传到 AutoDL”选择已有主机、远端父目录、Python 解释器并确认，使用已保存认证通过 SFTP 上传快照，远端校验 ZIP 哈希并解压到唯一快照子目录，写入 snapshot.json。不执行代码或安装依赖，不覆盖已有子目录。该操作使用独立短时 SSH 连接并在结束后关闭，不影响交互终端。界面显示处理中状态及最终路径，不提供字节级上传进度；最近 50 次上传记录保存在代码元数据中。失败可能留下独立的远端不完整目录，需人工确认清理。

“创建实验计划”固定当前快照并进入现有计划编辑页。填写研究目的、方法、评价协议、主机、Python、命令、数据引用和指标；确认计划仍执行环境预检查。复现计划不要求本地或远端 Git，但仍要求 Python、tmux 和 Bash 等 Runner 条件。

协议新增 code_source、reproduction_id、snapshot_id 和计划中的 reproduction 快照信息；旧 Git 计划兼容默认来源。正式运行走原队列、SFTP、日志、取消、重连及结果收集。Runner v2 对复现包校验后解压并逐文件检查哈希，恢复脚本可执行权限；实验代码沿用原 Git bundle 检出机制。准备脚本可从快照查看并单独授权执行。实验结果不虚构 git_commit，快照身份及来源保存在运行清单、环境和现有结果 environment.code_snapshot 中，保持结果可追溯。

新增项目级接口组 reproductions：列表、添加、编辑、移除、import、tree、file、snapshots、upload。均经过既有项目存在性检查，关联文献校验项目归属。文件和 ZIP 不作为代码改动提交。
