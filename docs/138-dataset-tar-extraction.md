# 数据集 TAR 压缩包自动解压

分支 ct_dev_test，基线 ffb900b，开始时工作树干净。已核对近期和上传文件相关历史、依赖目录和项目规范（未发现适用 AGENTS.md）。

## 原因及操作

之前仅 ZIP 显示解压选项，后台上传还强制将非 ZIP 的 extract 设为 false，服务端也仅接受 ZIP 解压。截图中的 .tar.gz 因此作为普通文件保存。

现支持 ZIP、TAR、TAR.GZ、TGZ 自动识别，上传弹窗沿用默认勾选的解压设置，后台持久上传正确保留选项。TAR 使用本地 Python 标准库检查每个条目：拒绝绝对路径、越界、控制字符、反斜杠、重复路径、软/硬链接及特殊文件、保留平台路径；限制 100000 条目及总展开量 5 GiB。流式计算解压文件 SHA-256 清单。远端检查 tar 工具可用，在本次独占创建目录内使用不覆盖、无归档属主权限恢复的选项解压；完成后移除临时包，沿用远端文件哈希核对及失败清理流程。ZIP 路径保持原行为。

## 自验、验收与遗留

仅源码及 Git 差异审阅，未执行测试、类型检查、lint、构建、浏览器、归档脚本、上传或远端解压。用户验收待执行。待核验 TAR/TAR.GZ/TGZ、默认解压选项、解压后哈希、异常条目与容量限制、ZIP 回归。

依赖远端 GNU tar，未自动安装。旧数据集不会自动重解压：本次没有读取或更改用户远端文件，已有目录也不会被覆盖。旧上传需要另行补解压，或使用新名称重新上传并绑定新记录。解压保持压缩包的原始目录层次，不自动展开嵌套压缩包。原始 JSON 归档解压不会生成 train.pkl/test.pkl/malicious.pkl，仍需源码规定的预处理。

重启服务并刷新后新上传生效；未重启、合并、推送或修改全局配置。
