# 通用运行目录检查与 Agent 分析修复

分支 ct_dev_test，基线 89fab9b。开始时工作树干净，核对近期及相关文件历史，依赖目录存在；项目检索及前轮各级检索无适用 AGENTS.md。应用 skill-creator 指导补充项目 Skill，未修改全局技能配置。

## 操作和版本

跑实验“检查运行目录”在原有输入、默认模型、工作目录、映射检查上增加实际目录展示。按数据集列出最多两层、500 项文件与大小，有限读取 metadata.json（64 KiB），不加载 pickle，不执行源码。

失败后“分析并修复目录问题”复用源代码 Agent 任务机制，固定源码快照，附检查结果、选择的处理方式/权重模式及原报告。Agent 区分原始数据、中间数据、可直接读取布局，按真实读取分支修正报告的子目录、前置输入和步骤；不针对任何具体项目硬编码。新报告保留源码行号证据和旧报告，禁止目录诊断模式直接应用源码补丁。

新模块跟踪分析、核对源码、权重补传、目录复查阶段，支持取消、恢复分析和显式再次修复。任务及检查结果在后端保存，浏览器保存项目/代码的任务 ID，刷新后继续查看；服务重启时正在应用的任务显示中断，可继续。每次点击仅执行一轮分析和应用，不无限自动重试。复查成功自动使用新报告并保存绑定，要求重新确认后才能启动实验。

## 修复边界

应用前比对实际远端源码与新报告快照的文件 SHA-256，本地源码变化或远端不同步时阻塞并给出同步代码的下一步，不覆盖远端源码。只自动采用有依据的报告修正及当前已选择绑定。

默认权重缺失且本地导入代码内有对应文件时，限定相对代码根、常见模型扩展名、最大 2 GiB，拒绝越界与平台敏感目录。仅在远端代码根内创建父目录，用排他方式创建目标，不覆盖现有文件；传输后比对 SHA-256。已有本地/远端默认权重会核对哈希，不一致时保留原文件并阻塞。取消或失败尝试清理本次创建的部分文件，已完成权重与操作记录保留，不删除公共数据。

预处理仍作为报告的独立 preprocess 执行步骤，在用户开始实验后由现有运行器执行并显示进度；目录检查本身不启动预处理或训练。缺少数据、下载来源未知、必须修改源码、默认权重无法安全补传等情况输出报告与下一步，保持阻塞。没有实现任意脚本自动修复、任意源代码改写或自动覆盖远端。报告所选方案在初始解析阶段已完全不可用时，仍需在源代码模块修正报告后才能启动本轮目录修复。
