## 操作流程

“分析源代码”改名“源代码”，操作栏为：导入源代码 → 开始分析 → 上传到 AutoDL。部署卡片移除重复上传按钮，复现中的文件浏览入口标为“浏览代码”；空项目仍保留首次导入入口。当前代码信息、任务进度和报告历史保留在工作区，上传弹窗及传输流程沿用原功能。

新分析使用 Skill 2.6.0，流程为固定快照/采集 → 分析 → 必要时备份并适配本地导入副本 → 重新采集和分析适配代码 → 校验/保存最终报告。原始快照、替换前后内容及变更原因均保留，最终报告重新生成源码依据和运行配置，不能只更新指纹。

Agent 只读输出最小 before/after 补丁，不直接写源码。平台仅对本次采集且 SHA-256 匹配的现有文件应用唯一替换，拒绝越界路径、符号链接末端、敏感目录、含脱敏占位符和歧义替换。应用前保存全部原文，写入失败尝试回写本批原文；原始 ZIP 用户文件和上游仓库不操作。只允许平台导入副本，不对任意绑定目录自动应用。

每任务最多一次适配；复核仍提出新补丁时停止并提示人工核对，防止无限改写/消耗 token。取消或中断后复用已保存阶段；适配状态不明时阻塞，不重复应用同一补丁。查看差异显示逐文件原文/新文；分析开始、继续和恢复前拒绝正在运行的实验。恢复按钮仅在当前内容仍等于本次适配结果时恢复备份，保留恢复前记录，拒绝覆盖后来人工修改。恢复后旧报告不再作为上传依据，需新分析。

## 路径及默认权重

数据路径参数化为实际绑定数据根，新权重、缓存及结果参数化为每次独立输出目录，保留原有非平台运行默认行为。算法、模型结构、划分、阈值和训练轮数不属于路径适配范围。不能推导正确改法时标阻塞。

已有权重不再显示历史模型下拉和浏览远端按钮，自动解析报告默认路径并只读展示。服务端采用报告路径，忽略客户端自选权重；固定默认加载逻辑正确时 loading:fixed，无须强造 weights 参数。未给出路径、文件不可读或缺失时仍阻塞，兼容性以真实加载为准。

采集脱敏收窄为完整凭据变量名及带引号的字面量值，不再因 token 数值/维度命名截断模型初始化表达式；已有密钥模式和敏感文件排除保留。分析材料脱敏并非完整的秘密检测工具，Agent 不得根据 REDACTED 猜原文。

## 上传门槛和兼容

上传弹窗打开前查报告及 freshness；真正生成上传快照后再以该快照的代码指纹核对 ready 的适配报告。未分析、适配未完成或当前代码改变时拒绝上传。当前实现要求静态适配 ready，但不把尚未运行表示成通过验证。已有远端代码和历史上传不自动覆盖。

旧报告继续可查看，但没有 adaptation 就不能作为新上传依据。继续旧任务仍保留原 Skill 内容；需“开始分析”生成 2.6.0 报告。
