# 部署进度、取消与断点继续

分支 ct_dev_test，基于 6493de5。开始时工作树干净，已核对部署执行器、快照校验、页面轮询、相关历史及依赖目录。

## 页面

部署记录改为进度卡片：Agent 方案、代码核对、虚拟环境、依赖安装、完成检查五个阶段。Agent 规划阶段不编造进度，使用不确定动画；远端阶段读取原子状态文件中的 completed_units/total_units，百分比表示真实已完成步骤，不代表网络下载字节进度。展示当前安装组、近期安装日志、成功/失败/暂停状态和运行前提醒。卡片沿用主题配色、渐变进度条、阶段勾选及窄屏布局，支持减少动画偏好。

## 后端与取消

本机 Agent 改用可管理子进程组，规划取消发送 TERM、必要时 KILL；没有启动远端安装时标已取消。远端使用固定 Python Runner，安装和 venv 创建各自启动独立子进程组，定期检查取消标记；先 TERM，等待八秒后必要时 KILL 并 wait，确认当前命令停止后才记录 cancelled。取消保留 .venv 和已完成断点，不删除包或系统环境，不断开用户终端。不使用旧 PID 远程杀进程。

任务目录 .trash-deploy-deploy_UUID 保存身份、状态、取消标记和安装日志，控制接口只使用平台记录的任务路径并核对身份。日志只返回最近约 10 KiB、服务端脱敏；远端日志超过 2 MiB 时截断旧内容。状态每约 0.5 秒更新，本地每两秒拉取。新增项目/复现记录范围的取消和远端状态刷新接口。

## 继续部署

相同报告、主机、目录及 Python 的再次部署优先复用前次 plan.json，避免模型重规划导致环境漂移。远端 .trash-venv-checkpoint.json 记录计划/代码指纹/解释器身份、venv 创建状态、已完成安装组及依赖清单摘要；.trash-venv.lock 使用 Linux flock 防止同目录并发安装。只有平台当前计划的环境可继续，不自动接管陌生 .venv，不清空已有包。

每个安装组成功并保存包清单后才记录完成断点。取消在某组中途发生时重新尝试该组，pip 复用已满足依赖和可用缓存；不承诺 ZIP/wheel 下载的字节级断点续传。恢复时若包清单被其他操作改变，重新检查各安装组，pip 已满足的包不会强制重装。最后仍执行 pip check，不能用已有断点代替成功检查。

断线/服务重启不推断远端停止，保留 unknown；原 SSH 重新连接后读取远端真实状态，未完成或状态未知时阻止再次启动。无本机运行上下文的远端任务也可查询和取消。Runner 仍通过 SSH exec 启动，不承诺服务器重启后自动运行；如果进程无最终状态则保持待确认，需人工排查，不用过期心跳推断可安全重试。旧执行器创建且没有任务/环境标记的 .venv 不自动迁移或接管。

项目删除保护纳入未结束或状态未知的部署。代码哈希、选定 Python 版本、venv sys.prefix 及已有环境身份验证保留。单命令默认十五分钟，venv 创建三分钟，总部署约三十分钟；环境盘点等短检查受独立超时限制。
