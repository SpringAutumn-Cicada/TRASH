# MVP 实施计划

- 文档版本：0.1
- 目标：交付 APT 检测与溯源研究闭环
- 原则：每阶段均有可运行验收，不以静态界面或 Agent 演示代替功能闭环

## 1. MVP 范围摘要

本地部署的 TypeScript 工作台；本机 Codex CLI；Codex Skill 格式；APT 配置型研究模块；用户导入文献与公开检索入口；项目级 RAG；本地烟囱实验；通用 SSH 远程全量实验；Git commit 作为代码版本；研究方案、实验报告、论文初稿；期刊格式、结构和清单检查。

## 2. 分阶段计划

### Phase 0：仓库与协议基线

交付：

- 仓库脚手架、开发命令、代码质量配置、CI 基础。
- Domain ID 与协议版本规则。
- `ResearchProject`、`WorkflowRun`、`AgentTask`、`ExperimentTask`、`Artifact` 最小 Schema。
- 文档中未决技术选择形成 ADR，不隐式拍板。

验收：从空环境安装依赖、启动本地工作台、运行 typecheck/test/build；协议示例可校验。

### Phase 1：本地项目与文献（已实现首版）

交付：

- 创建和打开项目。
- 本地元数据持久化、项目目录约定、导入文献。
- PDF 文本解析与来源定位。
- 文献搜索 Provider 接口，Google Scholar 辅助检索入口。
- 项目级检索与 RAG；结果返回来源和定位。

验收：导入一组真实 APT 文献，检索结果可定位到原文页码/段落；重启后项目状态保留。首版工程基线使用 SQLite + FTS5、Vite + React、PDF/BibTeX/RIS/Markdown/网页导入、OpenAlex Works 搜索与 Scholar 用户触发入口；向量检索延后。实现范围和网页抓取安全边界见 [ADR 0002](adr/0002-phase-1-local-literature.md)。自动化验收以本地合成文档 fixture 验证定位和重启持久化；真实文献导入仍需用户在本机手工验证许可与解析质量。

### Phase 2：Codex 与工作流

交付：

- 本机 Codex CLI 检测、配置、运行、取消、事件/日志收集。
- 工作区权限默认配置与用户可调整配置。
- `.codex/skills/` 下首批 Codex Skills。
- APT 问题、研究缺口和方案结构化对象。
- 人工确认与版本记录。

验收：Codex 能在选定项目工作区生成研究方案候选；结果通过 Schema；方案需经用户批准才进入实验准备。

### Phase 3：Git 与本地烟囱实验

交付：

- Git 状态检测和 commit 基准固定。
- 本地 smoke run 执行与日志/配置/指标登记。
- 指标与图表 artifact 格式。
- 实验报告模板。

验收：同一 commit 和配置能够创建可区分的实验运行记录；dirty tree 按 MVP 规则阻止或转入显式快照流程。

### Phase 4：通用 SSH 与 AutoDL 实测

交付：

- SSH profile、连通性诊断、远端初始化脚本。
- 远端工作目录、任务 manifest、提交与状态查询。
- Git commit 固定、环境检测、日志和小型产物回传。
- 大型数据远程引用与 hash 记录。

验收：在真实 AutoDL 实例上完成烟囱级远程运行和一次全量任务演练；不覆盖用户创建实例时选定的基础环境；断开后可以重连任务。

### Phase 5：分析、写作与期刊格式

交付：

- 分析版本和投稿目标分析对象。
- 由已确认方案、实验和引用生成报告/论文初稿。
- 主张与来源/结果的关联和待审标识。
- Journal Module 格式、结构、投稿清单检查。
- Markdown 及首版确定的交付格式导出。

验收：输出的论文结果段落能回指实验数据；引用可定位；未证实结论被标记；期刊模块只检查用户选定目标的要求。

### Phase 6：内测与发布准备

交付：

- 使用本人真实课题和同学试用反馈修复可用性问题。
- 项目导出/恢复、失败诊断、配置备份。
- README、安装/运行说明、贡献指南、许可证决策和问题模板。

验收：新用户按文档可在本机启动，创建项目并完成示例流程；数据和项目可导出并恢复。

## 3. MVP 验收课题

使用一个真实 APT 检测与溯源研究任务进行端到端验收。测试材料至少包括：

- 一组用户导入的参考论文。
- 一份结构化研究问题和约束。
- 一个已纳入 Git 的代码仓库与 commit。
- 一个适合 smoke run 的小数据切片和全量数据远程引用。
- 本地 smoke run 与 AutoDL 远程 run。
- 预期指标、图表、报告和论文草稿段落。

这组数据作为回归测试 fixture 时需确认许可和脱敏要求；不得把私有文献全文或敏感数据提交到公开仓库。

## 4. 首版工程质量门槛

- 领域 Schema 和 Runner/Agent 协议有单元测试。
- 工作流暂停、失败、重试和事件持久化有集成测试。
- SSH 流程使用可控 fake server 或本地测试容器测试，再做真实 AutoDL 手工验收。
- 核心 UI 流程至少有浏览器级冒烟测试。
- Codex Adapter 通过 stub CLI 契约测试；真实 CLI 验收单独执行。
- 远程任务日志对密钥和令牌做脱敏测试。
- 导出项目后可在新目录恢复元数据和文档引用。

## 5. 主要风险及应对

| 风险 | 影响 | 应对 |
|---|---|---|
| APT 工作流抽象过拟合当前研究 | 后续模块难接入 | APT 模块先做，内核仅保留通用项目、任务、证据和产物类型 |
| Codex CLI 行为或输出变化 | 任务运行失败或事件解析失效 | CLI 细节封装 Adapter，版本检测、契约测试和原始日志留存 |
| AutoDL 环境差异 | 初始化脚本误改环境或实验不可复现 | 先只检测和准备项目目录，依赖安装需审阅确认，真实主机验收 |
| Scholar 搜索自动化受限 | 文献检索接口不稳定或违反规则 | 用户触发浏览器辅助搜索与导入，不批量抓取 |
| 大数据同步成本高 | 任务时间、磁盘和流量不可控 | 首版远程引用 + hash；先测 SSH/SFTP、挂载和远端仓库能力再选方案 |
| Agent 生成无来源结论 | 论文不可信 | Claim 状态、证据链接和审阅门槛；没有来源的事实标记待审 |
| 模块插件执行任意代码 | 本地数据和主机风险 | MVP 模块只允许声明式配置、Schema 和模板 |

## 6. 实现前待定项

以下不是用户尚未回答的产品决策，而是应在对应实现阶段通过仓库检查或小型验证选择的工程方案：

- 本地 UI 是否采用纯浏览器工作台或桌面壳；推荐先 localhost Web。
- 前端具体框架与当前 R2R 代码的复用范围。
- SQLite 之外是否需要更换本地数据库。
- PDF 解析、向量索引和 embedding 实现。
- 首批公开学术检索 Provider 清单；Scholar 采用何种浏览器辅助交互。
- Codex CLI 当前稳定调用参数和事件捕获方式。
- AutoDL 远端任务持久化方式、Git 同步策略和初始化脚本细节。
- Markdown、DOCX、PDF 中哪种是首版主导出格式。
- 项目许可证、商标/名称可用性与开源发布流程。

每项需要明确结论的选择应记录为 ADR，写明上下文、选择、备选和迁移影响。
