# Agent 修复部署

失败的部署卡片增加“Agent 修复部署”，需要原主机已连接且没有其他部署进行。与继续部署不同：继续复用方案，修复则读取原日志和方案，执行固定只读探测采集实际解释器、venv、pip、安装包、wheel tags、GPU，再调用一次本机 Agent 分析。分析会消耗 token，安装、日志和进度采集仍由脚本完成。继承现有 CLI 默认权限，不修改全局配置。

Agent 可只读查阅官方文档和 wheel 列表，输出诊断、解决步骤、来源及结构化安装方案。支持按安装组拆分 index_url，增加 extra_index_urls、find_links，解决例如 PyTorch 专用源遮蔽 DGL 分发包的问题。具体是否有 dgl==1.0.0 的兼容 wheel 由实际查阅和安装判断，没有硬编码成功结论。没有兼容 wheel 时明确提示可用的镜像/解释器调整，不编造地址。

服务端校验输出大小与结构、HTTPS 无凭据来源、新安装源依据，以及原依赖规格保留；不能悄悄升级、降级、删包或替换包名。runner 汇集方案的版本约束作为 pip constraints，避免后续组间接覆盖固定框架版本。保留系统环境和解释器，不执行 Agent 给出的任意 Shell 安装脚本。

修复更新原部署卡片，展示诊断、步骤与来源。每次点击一次分析，无无限自动重试。原方案、失败上下文和修复输出保存在任务目录。代码和解释器身份相符时，将旧断点迁移到修复方案，备份原 checkpoint、保留 .venv，重核对所有安装组；pip 复用已满足依赖和缓存。陌生 venv 不自动接管。取消、超时和已有进度保持适用；状态未知时必须先刷新确认停止，不能同时安装。
