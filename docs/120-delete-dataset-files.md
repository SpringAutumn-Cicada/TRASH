# 删除数据集与远端文件

数据集详情新增“删除数据集”，保留原仅删记录操作并更名“取消登记”。删除按钮要求原主机已连接，弹窗展示名称、主机和完整路径，确认后删除远端该路径全部内容以及登记。处理中按钮反馈等待状态；不执行真实删除作为开发验证。

新增 POST datasets/:id/delete-files，要求 confirm 与当前 path 一致，服务端重新读取记录后检查：无本项目数据传输/部署占用、无活动实验与运行/暂停复现队列引用。只允许当前项目工作区 datasets 下的独立数据路径，拒绝父目录/系统目录、代码上传目录、与其他本项目数据集重叠、路径中的符号链接以及失败/取消上传对应目录（后者可能从未属于本次上传）。使用 SFTP lstat 逐层检查，再通过带独立参数的 rm -rf --one-file-system -- 删除，不拼接任意 Shell。已不存在的路径可以取消登记；远端命令失败保留记录，成功才删除数据库登记。该行为永久删除，不是回收站；手工在平台之外引用同目录无法自动识别，用户确认前需核对。项目规范目录外的已有数据可取消登记，文件需自行处理，平台不扩大目录删除权限。

历史实验计划/结果及数据集哈希基线保留供追溯，不级联删除。普通目录删除使用现有持久SSH连接，不自动连接新主机。远端文件删除与本地数据库删除不具备跨主机原子事务，若远端已删后本地失败，可重试消除残留登记；外部并发修改目录不受平台锁控制。

分支 ct_dev_test；开始工作树干净、依赖存在，已核对数据集路由、工作区与活动引用和相关历史，未发现仓库 AGENTS.md。开发自验仅静态审阅，不运行 lint、类型检查、测试、构建、浏览器、SSH 或实际删除。用户验收待进行：成功删除、未连接、正在使用、共享路径、符号链接、目录已不存在、删除失败保留记录和外部目录拒绝。需要重启后端并刷新页面；本次未主动重启、合并、推送或修改全局配置。
