# 复现实验运行模式与主机资源选择

## 版本与操作范围

## 运行模式

Skill trash_analyze_code_environment 升级为 2.4.0，每套执行方案增加明确 mode：

- train：从头训练并评估，不默默加载已有权重。
- evaluate：已有权重评估，不执行训练步骤。
- resume：加载源码支持的完整训练状态，继续训练并评估。

同一数据集集合在不同模式下分别生成方案。模式切换后只列该模式的方案与其适用数据集；没有识别支持时提示不支持/待适配。历史报告仍可查看，缺少 mode/model_input 时自动入口提示重新分析，手动高级模式继续兼容。

每个数据集包含模型输入种类、报告默认路径、兼容要求和源码证据。评估必须绑定 weights，继续训练必须绑定 checkpoint，且报告命令/配置必须实际引用相应占位符。单纯权重初始化不是完整恢复；加载入口和关键参数缺失时保持 blocked。

## 权重与检查点

每个数据集可从本项目同主机、同源码数据集且已记录种类的历史模型产物中选择，也可以打开远端文件浏览弹窗。报告明确默认路径时可点击采用该路径。文件存在、结构兼容和完整训练状态是不同条件：运行前只核对文件存在，兼容性要求在界面展示，最终由实际加载确认。

模型输出以有源码依据的 model_outputs 描述，并加入运行产物清单。大于现有回传上限的文件保留远端路径/哈希，不强制下载到本机。记录丢失或文件已删除时不能保证历史路径仍可用，启动前再次检查。不支持以模型目录代替文件；复杂目录模型需在报告标明待适配。

执行计划保存模式、模型输入、资源策略和产物信息；结果记录附带模式及模型来源元数据，不改变传给源码的原始实验配置。

## 计算资源

新增只读 compute-resources 接口，复用已连接 SSH，以固定 nvidia-smi 查询读取编号、UUID、型号、总显存和空闲显存，并遵守 SSH 环境明确设置的 CUDA_VISIBLE_DEVICES。未安装工具或读取失败时展示未知/失败，绝不生成虚假的 GPU 0。显存 N/A 保持未知，不填零。

主界面及兼容高级界面均使用选择控件，移除手写 GPU/cpu 输入。默认按报告 CPU 建议或已发现 GPU 的可用显存推荐，用户可点选其他设备；资源信息加载时显示进度，可主动刷新。GPU 方案在未发现 GPU 时不自动降级为 CPU，允许用户仅在方案未明确禁止 CPU 时主动选择 CPU，并提示支持性未知。

CPU 明确不支持时禁用。只有报告有真实多 GPU 启动依据时允许多选；启动参数使用源码自动检测数量或 gpu_count 模板。CUDA_VISIBLE_DEVICES 设置后物理设备重新映射到进程内逻辑编号，报告应按该规则生成参数。模板新增 weights、device、gpu_count，并沿用 checkpoint。

提交前和任务实际启动前重新核对资源，GPU 消失、CPU 不支持、未经声明的多 GPU 组合均停止。可用显存仅代表查询时快照，不保证实验显存充足或独占；MIG 等不能由当前查询明确匹配的设备不伪装为可用普通 GPU。
