# 部署阻塞与运行提醒分离

分支 ct_dev_test，基于 e0687e4。开始时工作树干净，核对相关提交及依赖目录。使用 skill-creator 的既有规范更新项目 Skill，遵守 trash_ 前缀及本轮不运行验证的要求。

问题：旧分析将数据、权重缺失、未锁版本与静态未验证等全部列为 blocked，UI 和服务端据此拒绝启动部署规划，导致已有报告仍无法点击。

本次优化：v2 报告不再仅因 blocked 状态禁用按钮或拒绝部署请求。点击后由部署 Agent 使用报告及原分析的已筛选 input.json 重新分类，只有生成可执行的安装计划才开始远端写入。真正安装阻塞保留停止行为；运行前提醒另存 warnings 并在任务中显示。数据/权重/缓存/评估条件与尚未验证不阻止创建环境。普通依赖映射明确时允许未锁版本交由 pip 求解，仍保留已有框架和依赖约束，不伪造固定版本；失败如实记录，不保证兼容。

Skill 更新至 2.1.0，新增 runtime_notes，协议作为可选字段兼容已有 v2；服务端报告元数据同步版本。旧 blocked 报告可直接交给规划 Agent 重新分类，无需强制重新分析。新版页面展示实验运行前提醒。主机未连、解释器缺失、时效未确认等其他不可点击原因直接显示，避免按钮无解释地禁用。

未放宽代码时效、上传快照一致性、主机连接、解释器校验或 venv 隔离；未知关键发行包/构建、约束冲突及必须系统修改等仍可阻止安装。GPU 兼容性如果明确使选定构建不可安装，不能一律当提醒忽略。没有自动修改旧报告或调用模型。

实际仅源码阅读与编辑，未执行 lint、类型检查、测试、构建、Skill 验证脚本或浏览器验证，未调用 Agent、未连接 AutoDL、未执行安装。尚未测试，用户验收未执行。待集中验证旧 blocked 报告、真正阻塞停止、未锁依赖求解及约束保持、warnings 持久保存展示、未连接/无解释器/报告过期提示。未合并、未推送、不修改全局配置。
