# 论文项目本地工作区与整体迁移

## 操作入口

新建项目时选择运行 TRASH 的本机根目录、填写项目文件夹名称，并查看完整路径预览。默认根目录为 TRASH_HOME/workspaces；记住上次成功创建时选择的根目录。目录选择器可浏览本机路径、进入上级及创建文件夹，不初始化 Git。当前 WSL 部署使用 WSL 路径，Windows 磁盘可用 /mnt/c 等挂载路径。

进入项目后，右上角“项目操作 → 本地工作区 / 迁移”显示当前实际路径、外部引用及迁移进度，提供打开目录、选择新根目录、设置并迁移/迁移工作区。首次为旧项目设置时也使用完整迁移流程，不自动改变已有项目目录。

目标必须为已存在且可写的根目录下尚不存在的项目文件夹。拒绝已有同名目标、项目之间相互嵌套及平台内部数据库/任务目录。默认 workspaces 是平台数据目录中的专用例外。项目名称不是身份，固定 project_id 保持不变。

## 目录布局

```text
论文项目/
├── project.yaml
├── literature/
│   ├── originals/
│   ├── parsed/
│   └── cards/
├── wiki/
├── research/
├── code/
├── data/
├── experiments/
├── manuscript/
├── exports/
└── .trash/
    ├── knowledge-history/
    ├── knowledge-state/
    ├── knowledge-pending/
    └── project-records.json
```

原有 raw 目录在迁移副本中整理为 literature/originals，并保留 raw 相对符号链接；其他既有运行、复现、任务目录保留，保证原代码路径兼容。平台 projects/<项目ID> 是指向实际工作区的稳定符号链接，数据库 managed_files 中的既有相对路径无需重写。没有将用户选定路径塞入科研项目协议，避免知识包恢复时绑定到别人的磁盘。

原有 agent-workspace/manuscripts 在 manuscript 为空且无路径冲突时移入 manuscript，原位置保留相对链接；两边都有内容时保留两边，不自动覆盖。新项目 Agent 目录中的 manuscripts 指向 manuscript。

literature/parsed 保存原文解析片段及页码/段落 JSON；本次只规划图片存放位置，未增加 PDF 图片提取、页面渲染或 OCR。

## 卡片和 Wiki 文件

配置工作区后，卡片位于 literature/cards/<对象ID>.md，Wiki 位于 wiki/<对象ID>.md，正文和可编辑元数据保存在文件中。YAML front matter 使用单行 metadata JSON 值（JSON 也是有效 YAML），含项目/对象 ID、类型、base_version、审核状态及结构化内容；卡片正文保留固定中文栏目标题，数据集、指标和证据等保留在 metadata.content 中，Wiki 正文为自由 Markdown。

保留 metadata 的 ID/类型/base_version 和卡片栏目标题后，可直接编辑现有文件。平台读取最新对象、列表或历史前会检测变化，通过原有 schema、来源、依赖和版本校验建立新草稿版本；审核状态不能通过编辑文件变为已采纳。旧页面使用旧 base_version 提交时拒绝覆盖，同时保留已导入的文件编辑。历史版本和审阅日志仍在数据库，历史 JSON 同时保存到 .trash/knowledge-history。历史采纳版本保留。

本地文件是当前可编辑内容来源，数据库提供版本化索引和查询。文件格式无效、版本冲突或已管理文件被删除时明确拒绝继续写入，保留文件与数据库历史；不能静默用数据库覆盖。写入通过发布日志保护，进程中断或外层数据库事务回滚后，下次读取按已提交版本恢复文件；发布后外部新增的合法编辑会保留并参与同步。请勿手动修改 .trash 同步/历史文件。

首版通过读取时同步，尚无文件监听；不自动发现未知 ID 的新 Markdown，不把文件删除当作知识对象删除。新建和删除对象仍走平台支持的入口。发生冲突可对照 .trash/knowledge-history 的版本 JSON 恢复文件元数据及正文，不提供自动合并冲突按钮。

## 整体迁移与恢复

1. 项目存在 Agent、知识任务、上传、复现、环境分析、目录修复、实验或 SSH 终端时拒绝迁移；有其他在途项目请求时也拒绝。
2. 取得项目迁移占用，阻止新的项目操作，仅允许工作区状态轮询；先同步已有外部 Markdown 编辑并保存迁移时的项目记录快照。
3. 在目标根目录建立唯一临时目录，检查可用空间，复制整个项目目录，按文件数与字节显示进度。
4. 对普通文件校验 SHA-256，复查源文件哈希、目录清单和符号链接，源文件在迁移中变化则失败。符号链接不跟随复制：项目内链接调整为相对引用，外部链接保持原目标并列出。
5. 校验成功后整理目标布局，以平台稳定入口切换实际目录；本地实验对象中指向原物理工作区的绝对路径同步更新，外部引用保持不动。
6. 源目录作为迁移备份保留。迁移备份列表可查看多次迁移的历史备份；清理必须单独确认，并核对目录归属、是否仍被项目使用及是否包含当前工作区。有迁移后处理警告时不允许清理。

迁移记录位于平台数据目录 workspace-migrations，不放进正在复制的项目目录。关闭弹窗或浏览器不取消后端迁移。服务重启时，切换已生效的记录完成路径重绑定；未切换的标为中断，源目录继续使用，必要时恢复临时移走的旧入口。失败副本保留供排查，用户可选择新的空目录重试；不会自动清除恢复材料。不承诺在平台外部程序持续写入时获得一致快照，应先停止外部编辑与训练。

平台 SQLite、SSH 凭据和全局配置留在平台数据目录。项目记录快照是迁移时的备查数据，不是独立数据库或自动恢复包；平台数据库仍需单独备份。外部仓库、工作区外数据与远程文件不搬动，界面按已登记路径列出外部引用；符号链接清单在复制过程中补齐。

删除项目记录时，独立工作区保留，界面提示用户确认后手动清理。原有未设置独立工作区的项目沿用旧删除逻辑。
